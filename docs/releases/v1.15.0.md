## Overview

v1.15.0 为数据地图资产加入协作评论线程（FYOIP-20）：每张数据地图表获得一个工作空间隔离的评论 Tab，评论为扁平列表、支持单层回复，正文纯文本、`@` 记号由前端渲染为高亮标记；每用户每资产维护一个已读水位，未读数以独立端点供 Tab 标签展示徽标。评论的增删与未读推进全部走服务端校验：回复必须指向同资产的顶层评论，删除仅限作者本人，评论目标必须是存在的数据地图表。迁移为纯新增两张表，不改任何既有表与接口。

## Highlights

- **扁平线程 + 单层回复**：顶层评论按新到旧分页，回复在各自父评论下按旧到新嵌套；回复不能再有回复（`COMMENT_PARENT_MISMATCH`），跨资产回复同样被拒绝。
- **未读水位**：`yak_ops_data_map_comment_read` 按用户与资产唯一，`ON DUPLICATE KEY UPDATE` 幂等推进；未读数 = 晚于水位且非本人发表的评论数。打开 Tab 即推进水位，徽标随之清零。
- **纯文本正文**：服务端只存纯文本，不解析、不解析成员、不下发 HTML；`@` 记号在前端按词边界渲染为非交互高亮块，不携带任何送达承诺。
- **服务端强制规则**：正文 ≤ 2000 字符（`COMMENT_TOO_LONG`）、评论目标必须为存在的 `DATA_MAP_TABLE` 资产（`COMMENT_TARGET_INVALID`）、删除仅限作者（`COMMENT_NOT_FOUND` / `COMMENT_FORBIDDEN`）。
- **标准分页形态**：`GET /api/v1/data-map/comments` 返回仓库统一的 `PagingData` 结构，未读数由 `GET /unread-count` 单独提供，Tab 标签无需加载线程即可展示徽标。

## New Features

- **资产评论 Tab**（资产详情页）：评论输入框（Ctrl+Enter 提交）、顶层线程展开回复、回复自动预填 `@作者`、作者可删除自己的评论、Tab 标签未读徽标。
- **评论 API**：`/api/v1/data-map/comments` 提供 `GET /`（分页线程）、`GET /unread-count`、`POST /`（评论或回复）、`DELETE /{commentId}`（作者删除）与 `POST /read`（推进已读水位）。
- **错误码**：19723–19727（正文超长、父评论不匹配、评论不存在、非作者删除、评论目标无效）。

## Improvements

- 回复读取收敛为单语句按目标查询（`repliesOfTarget`），服务端按父分组，一页线程不再逐条发起 N+1 查询。
- 评论 ID 使用统一雪花生成（`IdUtils.nextId()`），审计列沿用模块 `initCreate(actor)` 惯例，与 V10–V12 姊妹表一致。

## Bug Fixes

- 本版本为评论功能首次交付，无既有缺陷修复；评审阶段修复了实现草稿中的作者名误存用户 ID、删除接口缺失鉴权、回复未校验同资产三类问题，均未随任何已发布版本出库。

## Breaking Changes

- 无。本版本全部为新增接口与新增表，未修改既有契约。

## Compatibility

- 数据库：MySQL 8（InnoDB、`utf8mb4_unicode_ci`），沿用 64 位应用侧生成 ID 与 `DATETIME(3)` 约定；`parent_id` 外键 `ON DELETE CASCADE` 保证删除顶层评论时级联清理回复。
- 运行环境：JDK 21；单节点部署边界不变。
- API：`/api/v1/data-map/comments` 为新增；数据地图其余接口不变。
- 前端：React 单页应用，评论 Tab 挂在既有资产详情页 Tab 组内，沿用数据地图既有键与请求封装。

## Upgrade Guide

1. 备份元数据库。V13 为纯新增迁移，回退仍以恢复升级前备份为唯一受支持路径。
2. 用 1.15.0 的分发包或镜像替换旧版本，启动时 Flyway 自动应用 `V13__v1_15_0.sql`，无需人工数据修复。
3. 升级后资产详情页出现「评论」Tab；既有功能行为不变，未配置评论的资产显示空线程提示。
4. 若需回退到 1.14.0，需同时恢复备份；两张评论表不会被任何脚本删除。

## Known Limitations

- 评论只能挂在数据地图表上；列、模型、指标等其他资产类型与多态目标需要后续提案。
- `@` 记号仅为视觉高亮，服务端不做成员解析、不发通知；真实提及送达需要独立的通知设计。
- 删除仅限作者本人；工作空间管理员代删需要角色解析能力，本版本不提供。
- 评论不可编辑（编辑 = 删除 + 重发）；无表情、点赞、附件与全局评论流。
- 目录当前没有资产删除流程；当未来引入时，其所有者必须级联清理锚定评论。
- 前端线程一次加载前 50 条顶层评论，暂无翻页控件；更早的评论需等后续分页入口。
