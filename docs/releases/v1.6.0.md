# Yak Ops v1.6.0

**Released:** 2026-10-24

本文件记录 1.6.0 版本的既定产品行为。本仓库尚未为该版本创建 Git Tag 或 GitHub Release，发布状态见 [Releases 索引](README.md)；下文 Downloads 与 Compatibility 描述的是当前实际可获取的内容。

## Overview

本版把维度建模补到最后一步：逻辑模型可以直接发布成物理表。发布时由用户显式指定目标库与 Schema，系统按引擎方言生成建表脚本，表不存在就创建、已存在就按模型校验而绝不修改，并把每一次发布都记为一条不可变记录。发布成功后还会采集该表的物理结构，形成一份可重新采集的元数据快照。至此 `DWD` / `DIM` / `DWS` / `ADS` 四种模型都能落到真实引擎上。

## Highlights

- **发布就是「创建或校验」：** 目标表不存在时执行建表；已存在时逐列比对结构，一致则记为成功，不一致则记失败且不修改目标表（[YOIP-11](../yoips/YOIP-11-physical-publish-and-metadata-collection.md)）。
- **目标地址只能显式选择：** 数据库必选，Schema 在 Oracle 与 PostgreSQL 必选、在 MySQL 必须不选；地址不会从分层默认值、表名或分层编码推断。
- **发布记录不可变：** 每次发布先落一条 `PENDING`，再写终态；连接中断无法确认结果时记为 `UNKNOWN`，只能通过对账解决，对账不会重跑 DDL。
- **元数据快照随发布产生：** 成功后采集该表与全部列，重复采集整份替换；采集失败不影响已经成功的发布。
- **数据库仍只有一处前向迁移：** `V4__v1_6_0.sql` 只新增 4 张表，不修改任何既有表结构，也不读写既有数据。

## New Features

**发布物理表**

- 模型列表与模型编辑器都提供「发布」入口；对话框从数据源 Catalog 读出数据库与 Schema 供选择，展示将要执行的脚本，勾选确认后才可发布，发布结束后展示终态结果。
- 分层未启用或未绑定数据源、模型没有字段、数据源类型不在支持范围内时，发布在生成脚本之前就被拒绝，不会留下待执行记录。
- 支持 MySQL、Oracle、PostgreSQL 三种引擎；其他引擎（湖格式、计算引擎）在开始时即被拒绝。
- 物理表名就是模型名，发布不会改名；发布时以已保存的模型定义为准，编辑器中未保存的修改不参与生成。

**DDL 生成**

- 字段顺序按模型序号，主键按主键位置排序，与后续校验使用的顺序一致。
- 类型矩阵：`STRING` 必须填写长度且不超过引擎上限（MySQL 65535、PostgreSQL 10485760、Oracle 4000）；`DECIMAL` 必须填写完整的精度与小数位，精度 1–38 且小数位不超过精度；`BIGINT` 在 Oracle 建为 `number(19)`；`TIMESTAMP` 在 MySQL 建为 `datetime(3)`。
- 主键列一律声明 `NOT NULL`；字段描述在 MySQL 写成内联 `COMMENT`，在 Oracle 与 PostgreSQL 写成尾随的 `COMMENT ON COLUMN` 语句。
- 分区、聚合方式、存储策略与生命周期不进入脚本：它们是本版的逻辑属性，缺少各引擎的物理设计对应物。

**发布记录与对账**

- 每次发布记录目标数据源、数据源版本、地址、表名、脚本、状态、错误、发起人与时间；同一模型的历史按时间倒序返回最近 50 条。
- 发布请求对任何终态都返回该记录，失败不会被折叠成一个通用错误：界面因此能直接展示「哪一列与模型不一致」，而不是只提示「发布失败」。
- 状态迁移只有两条路径：`PENDING` 到终态，`UNKNOWN` 到终态；对已终态的记录再写一次不会生效。
- 连接类故障（`SQLState` 以 `08` 开头、超时、连接中断）记为 `UNKNOWN`，其余引擎拒绝记为 `FAILED`；错误文本截断到 1000 字符。
- 对账只重新读取目标表：表不存在记为 `FAILED`，结构一致记为 `SUCCEEDED`（并补采元数据），不一致记为 `FAILED` 并写明差异。

**元数据采集**

- 发布成功后采集目标表与其全部列，保存库名、Schema、表名、表类型、表注释，以及列的序号、原生类型、`java.sql.Types`、长度、小数位、可空、主键位置与注释。
- 「重新采集」只对发布成功的记录开放，且整份替换上一次快照：新快照写入与前一份删除在同一事务内完成，采集失败时旧快照仍然可用。

**REST 端点（均为增量）**

- `POST /api/v1/data-modeling/dimension-modeling/models/{modelId}/publications/preview` 只生成脚本，不写记录。
- `POST /api/v1/data-modeling/dimension-modeling/models/{modelId}/publications` 执行并记录一次发布。
- `GET /api/v1/data-modeling/dimension-modeling/models/{modelId}/publications` 返回该模型的发布历史。
- `GET /api/v1/data-modeling/dimension-modeling/publications/{publicationId}` 读取单条记录。
- `POST /api/v1/data-modeling/dimension-modeling/publications/{publicationId}/reconcile` 对 `UNKNOWN` 记录对账。
- `GET|POST /api/v1/data-modeling/dimension-modeling/publications/{publicationId}/metadata[/refresh]` 读取或重新采集快照。

## Improvements

- 新增错误码 `19514`（元数据采集失败，HTTP 502），与既有维度建模错误码同段编号；发布失败没有专属错误码，因为失败本身是一条返回给调用方的记录。
- 数据源引擎白名单抽成共享模块，逆向建模与物理发布使用同一份定义，两类能力不会再出现「一个支持、一个拒绝」的偏差。
- 目标地址的校验规则抽成零依赖的纯函数并补 6 个单测：库/Schema 的选择、地址的展示形态，以及 MySQL 下不发送 Schema 的载荷归一化，都可在渲染之外验证。
- 模型列表操作列加宽到能容纳「编辑 / 发布 / 删除」三个动作。

## Bug Fixes

None — 本版为增量功能，没有独立缺陷修复。

## Breaking Changes

None — `V4__v1_6_0.sql` 纯新增 4 张表，无 `ALTER`；REST 只新增端点与路径，既有请求与响应形状不变；新增的错误码只出现在新端点上。

## Compatibility

- 运行要求 Java 21；Yak Ops 元数据库使用 MySQL 8。
- 升级路径覆盖 v1.5.0（即含 `V1` / `V2` / `V3` 的元数据库）。
- 发布记录与元数据表都以 `workspace_id` 隔离；`model_id` 在模型删除后被置空，历史记录因此不会连带消失，也不会被误认成「属于某个仍存在的模型」。
- 未验证的数据库版本、数据规模与部署组合不能作为正式承诺；可运行范围以本仓库 `master` 上 1.6.0 版本元数据对应的提交为准。本版尚未执行 Release Gate，也没有对应的 Git Tag、分发包与镜像。
- 本版未执行浏览器端自动化 E2E 或跨浏览器验收；新增的数据库集成测试需要 Docker，未在本机运行，验证边界见 Known Limitations。

## Upgrade Guide

**从 v1.5.0 升级：**

1. 先完整备份元数据库。V4 为前向迁移，仓库不提供回滚脚本。
2. 使用 1.6.0 的分发包或镜像直接启动，Flyway 会按版本顺序应用 `V4__v1_6_0.sql`。
3. V4 只建 4 张新表：`yak_ops_modeling_model_publication`、`yak_ops_modeling_metadata_collection`、`yak_ops_modeling_metadata_table`、`yak_ops_modeling_metadata_field`。
4. 既有逻辑模型、字段、分层与标准数据完全不受影响：本版不新增列、不回填、不改写任何既有行；没有发布过的模型自然不会产生记录。
5. 发布需要目标引擎可达，且数据源连接可用；升级本身不访问任何业务数据源。
6. 不要手工修改 `flyway_schema_history`，也不要用 `flyway repair` 跳过校验。
7. 需要回退到 v1.5.0 时，还原升级前的备份；不能假设旧版本可以直接读取已升级的库。

**全新安装：** 使用空的 MySQL 元数据库启动即可，`V1`、`V2`、`V3` 与 `V4__v1_6_0.sql` 会依次执行。

## Known Limitations

- **只支持三种 JDBC 引擎。** MySQL、Oracle、PostgreSQL 之外的引擎在发布开始前就被拒绝，不会生成脚本。
- **不产生 `ALTER` 或 `DROP`。** 目标表已存在时只校验：结构不一致记为失败，由人工处理；本版不提供改表、删表或数据迁移。
- **多语句脚本不做整体回滚。** 建表与尾随的注释语句按顺序自动提交；若建表成功而注释语句失败，表已存在但记录为失败，再次发布会进入校验路径并因注释不一致继续失败，需要人工修正。
- **物理表名与中文名不会同步。** 模型的中文表名不写入表注释，只有字段描述会进入脚本；表注释差异同样会被校验判定为不一致。
- **采集粒度是单表。** 只采集本次发布的表，不做全库采集、不做周期同步，也不产生血缘。
- **发布历史只有最近 50 条且不分页。** 更早的记录仍在库中，但界面不展示。
- **发布不使用编辑器中的未保存内容。** 编辑器中改了字段但未保存时发布，脚本仍按已保存的版本生成。
- **前端缺少自动化交互测试。** 页面逻辑由类型检查、静态检查与纯函数单测覆盖，异步交互未做浏览器实跑。
