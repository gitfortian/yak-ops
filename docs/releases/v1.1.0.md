# Yak Ops v1.1.0

**Released:** 2026-10-04

## Overview

在 v1.0.0 的单表同步能力上增加离线调度、失败重试、实时自动恢复和运维统计，让任务不必完全依赖人工操作。

## Highlights

- **离线定时执行：** Quartz Cron、时区配置、启停调度，重复触发使用 `SKIP_IF_RUNNING`。
- **失败重试：** 同一个 Execution 下记录多个 Attempt，失败历史与重试次数可追踪。
- **实时续跑：** 重启后恢复希望保持运行的实时任务，复用原 Task/definitionVersion 的 CDC 状态。

## New Features

- 离线调度：Cron 与 IANA 时区、下一次触发时间、调度开关、`SCHEDULE` 触发来源。
- 重试模型：`maxAttempts`、固定 Backoff、`RETRY_WAITING` 状态；人工停止或取消不会自动重试。
- 实时状态：区分发布状态、期望状态与执行状态；应用重启后创建新的 `AUTO_RECOVERY` Execution。
- 运维中心：离线/实时运行统计、状态分布、失败排行、最近异常与自动恢复记录。
- 离线执行诊断：Source Split、生成的 SELECT SQL、批次读写耗时；Trace 文件与只读诊断入口。

## Improvements

- Quartz 从 Yak Ops 数据库的调度定义恢复配置，数据库仍是调度配置的事实来源。
- 自动恢复保留 Workspace / Task / definitionVersion 的 CDC 状态身份，续传仍采用 at-least-once。
- Runtime Trace 为 best-effort，不持久化业务行值或 Sink 绑定参数，失败信息在落盘前脱敏。

## Compatibility

- 继承 v1.0.0 的 MySQL 单表离线 Source、MySQL CDC 实时 Source，以及 MySQL/PostgreSQL/Oracle Target 范围。
- 继承 Workspace、Datasource 和 Task 身份；产品版本与 Task `definitionVersion` 独立。
- CDC 状态仍按 Workspace / Task / definitionVersion 标识；**不保证 exactly-once**。

## Upgrade Guide

从 v1.0.0 使用本版向前迁移 `V2__v1_1_0.sql`，保留已发布的 `V1__baseline.sql` 不变。新增离线调度、重试/Attempt、实时期望状态及执行事件相关表结构。历史 Task 默认不自动重试；升级过程中活动且已发布的实时任务期望状态可能回填为 RUNNING。升级前备份数据库并保留 `${yak.ops.home}/data` 的 CDC/Trace 状态，按原始发布指南执行。

## Known Limitations

- 不支持分布式 Runtime/HA、exactly-once、自动建表、多表任务或 Transform。
- 不支持 PostgreSQL CDC；实时没有常驻 Watchdog。
- 重试策略没有独立的用户配置 UI；不支持跨进程持久化的重试计时器。
- Runtime Trace 不包含实时诊断、对象存储后端、保留策略或全文搜索。
