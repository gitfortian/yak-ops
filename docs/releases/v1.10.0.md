**Released:** 2026-10-27

## Overview

v1.10.0 把 v1.9.0 引入的数据地图采集升级为可运营的**元数据采集**：一次采集可以排除噪声表、失败后可以只重试失败表，列表展示触发方式、耗时与异常中断，让用户"敢用、爱用"。升级对既有资产只新增列、不改任何既有行。

## Highlights

- **忽略表正则**：提交采集时可配置正则（如 `^tmp_`）跳过噪声表；被跳过的表视为"确认存在"，保持正常状态，字段不重复采集。
- **失败表一键重试**：采集详情中列出失败明细，一键发起只包含失败表的新任务，其余表不受影响。
- **列表升级**：新增触发方式（手动/定时）、耗时与异常中断状态。

## New Features

- **忽略表过滤**（`V8` 迁移：`exclude_pattern`、`filtered_count`）：提交时输入 Java 正则，前端即时校验可编译性、后端二次校验（`CRAWL_PATTERN_INVALID`，19713）。匹配的表在本轮**刷新存活时间但不读取字段**，因此既不会成为新增/更新，也**不会**被缺失判定误标为"已缺失"；本轮未采集过的被排除表不产生任何资产行。详情弹窗显示"本次过滤了 N 张表"。
- **失败表重试**（`V8` 迁移：`retry_of`）：详情弹窗失败区新增「重试失败表」，发起一个只枚举原任务失败表的新任务（错误码 `CRAWL_RETRY_INVALID`，19714 校验来源）。重试任务**不做缺失判定**——它只对失败表负责，其它表的状态不受影响；由于目标表已存在，重试的"新增"恒为 0，正常情况只计"更新"。
- **异常中断状态**（`V8` 迁移：状态 CHECK 扩展 `INTERRUPTED`）：应用重启后，遗留的"采集中"任务统一标记为**异常中断**（灰色）而非"失败"，锁在同一条语句内释放，用户可立即重新发起采集。
- **列表升级**：新增触发方式（手动/定时，`trigger_type`）、耗时（提交到结束的墙钟时间）；变更统计含过滤数。
- **定时触发预留**：`trigger_type=SCHEDULED` 的数据模型与接口形态已就绪。平台调度器（Yak Flow）当前的目标类型仅支持数据开发任务（`TASK`），把元数据采集注册为调度目标是平台级需求，本版先交付数据模型与列表展示；配置定时任务暂由调度中心后续版本承接。

## Improvements

- 提交弹窗：数据源库列表加载失败时提供「手动输入库名」，不再阻塞采集。
- 采集详情：顶部信息条补充触发方式与耗时；过滤提示以说明形式呈现。

## Bug Fixes

- 继承 v1.9.0 修复：采集时间精度、`non_null` 序列化下的字段类型渲染、目录空状态与详情页重构（见 [v1.9.0](v1.9.0.md) 与 PR [#46](https://github.com/gitfortian/yak-ops/pull/46)）。本版无额外缺陷修复。

## Breaking Changes

- 无。`POST /api/v1/data-map/crawls` 新增两个可选字段（`excludePattern`、`retryOf`），既有调用方不受影响。

## Compatibility

- 数据库：`V8__v1_10_0.sql` 仅对 `yak_ops_data_map_crawl` 追加 4 列并扩展状态 CHECK 约束，不修改既有行；升级后元数据库结构停在 V8。
- API：v1.9.0 的全部接口保持兼容；采集 VO 新增只读字段。
- 前端：采集列表与详情按新字段渐进增强，旧数据（`trigger_type` 缺省按"手动"展示）不受影响。

## Upgrade Guide

1. 备份元数据库。本版会执行 V8 迁移，备份是回退到旧镜像时的唯一可靠手段。
2. 用 1.10.0 的分发包或镜像替换旧版本，启动时 Flyway 自动应用 `V8__v1_10_0.sql`。该脚本只追加列与约束，无需停机维护窗口。
3. 升级后无需任何数据修复：既有采集任务保持原状态，新的忽略表/重试能力从下一次提交开始生效。
4. 回退到 1.9.0 时，库中会多出 4 列与一条 V8 迁移记录。本仓库未验证旧版本对「更高版本迁移记录」的校验行为，因此回退应同时恢复备份，或先删除这些列并清理迁移记录。

## Known Limitations

- 定时触发需要平台调度器支持 `METADATA_CRAWL` 目标类型（见 New Features 的说明），当前版本由控制台手动触发。
- 忽略表正则采用 Java 语义的 `find()` 匹配：`^tmp_` 即前缀，无需写 `.*`；不支持逐表白名单。
- 重试任务沿用原任务的命名空间与失败明细上限（200 张）；失败超过 200 张时应先排查数据源权限再全量重跑。
