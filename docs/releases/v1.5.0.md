# Yak Ops v1.5.0

**Released:** 2026-10-24

本文件记录 1.5.0 版本的既定产品行为。本仓库尚未为该版本创建 Git Tag 或 GitHub Release，发布状态见 [Releases 索引](README.md)；下文 Downloads 与 Compatibility 描述的是当前实际可获取的内容。

## Overview

本版把维度建模的模型类型从「明细表 + 维度表」扩展到「汇总表 + 应用表」，让 1.4.0 已预置的 DWS / ADS 两层终于有对应的逻辑模型；同时为字段引入聚合方式，使汇总表与应用表得以表达「按什么函数聚合」这一核心口径。

## Highlights

- **汇总表与应用表开放建模：** DWS 挂公共层业务过程，与 DWD 同源归属；ADS 挂应用层数据集市，与应用层 DIM 一样需要指定归档分类（[YOIP-10](../yoips/YOIP-10-data-modeling-summary-and-application-models.md)）。
- **字段级聚合方式：** 新增 `SUM` / `COUNT` / `AVG` / `MAX` / `MIN` 五种函数，仅汇总表与应用表的字段可声明；`SUM` / `AVG` 只允许用于 `BIGINT` 与 `DECIMAL`。
- **数据库仍只有一处前向迁移：** `V3__v1_5_0.sql` 只给字段表增加一个可空列与三条 `CHECK` 约束，不修改任何既有表结构，也不读写既有数据。
- **入口随类型到位：** 维度建模树在业务过程节点新增「新建汇总表」，在数据集市节点新增「新建应用表」；模型列表与六维检索自动覆盖四种类型。

## New Features

**汇总表（DWS）**

- 归属与明细表一致：公共层「分类 → 数据域 → 业务过程」，不允许挂数据集市，也不允许绑概念维度。
- 至少需要一个带聚合方式的度量字段；其余属性（表名前缀取自分层编码、存储策略、保留天数、乐观锁）与既有模型完全一致。
- 更新时不允许改变模型类型，与明细表、维度表行为相同。

**应用表（ADS）**

- 归属应用层数据集市，并像应用层维度表一样记录归档分类；不允许挂业务过程，也不允许绑概念维度。
- 允许只包含维度字段（用于看板筛选），但通常应至少包含一个度量：零度量是合法形态，界面在类型说明中写明了这一语义。

**字段聚合方式**

- 字段编辑器在汇总表与应用表下新增「聚合」列，下拉选择五种函数或「无」；明细表与维度表不显示该列。
- 汇总表的「至少一个度量」在每次保存时校验（新建与编辑相同）：编辑器中最后一个度量行的删除按钮与「无」选项同时禁用，度量计数显示在字段统计行。
- 与逻辑类型存在兼容矩阵：`SUM` / `AVG` 需要算术运算，仅对 `BIGINT` / `DECIMAL` 可选；`COUNT` / `MAX` / `MIN` 对全部五种逻辑类型可选。
- 绑定数据标准后，聚合方式按标准解析出的类型重新校验，标准与聚合互相矛盾时保存被拒绝。
- 从物理表导入与 DDL 批量录入得到的字段一律不带聚合方式，由用户手工指定。

## Improvements

- `ModelType` 增加 `isPublicLayer()` 与 `allowsAggregate()` 两个判定方法，归属分派与字段校验共用同一份定义。
- 模型保存的归属分派由「DWD 走明细、其余走维度」改为按类型穷举分派，新增类型不会再被静默按维度表处理。
- `aggregate_type` 贯通 DTO、实体、MyBatis 注解 SQL 与 VO，列表与详情读取原样返回。
- 前端字段草稿、提交映射与导入路径同步携带聚合方式，导入未映射列仍保留待补全标记。

## Bug Fixes

- **字段描述可编辑并正确回显。** 逻辑模型字段表格新增「字段描述」列，使用既有 `description` 字段完成编辑、保存与再次打开时的回显；空描述仍按 `null` 处理，500 字上限与后端校验一致。

## Breaking Changes

None — `model.type` 本就没有数据库值约束，扩展枚举不产生 DDL；`V3__v1_5_0.sql` 为纯新增可空列与约束。REST 契约为增量扩展：`POST` / `PUT /models` 的 `type` 新增两个合法值，字段入参新增可缺省的 `aggregateType`，既有客户端不受影响。

## Compatibility

- 运行要求 Java 21；Yak Ops 元数据库使用 MySQL 8。
- 升级路径覆盖 v1.4.0（即含 `V1__baseline.sql` 与 `V2__v1_4_0.sql` 的元数据库）。
- `aggregate_type` 可空，既有明细表与维度表字段无需回填；不读取该列的既有部署行为不变。
- 未验证的数据库版本、数据规模与部署组合不能作为正式承诺；可运行范围以本仓库 `master` 上 1.5.0 版本元数据对应的提交为准。本版尚未执行 Release Gate，也没有对应的 Git Tag、分发包与镜像。
- 本版未执行浏览器端自动化 E2E 或跨浏览器验收，前端交互的验证边界见 Known Limitations。

## Upgrade Guide

**从 v1.4.0 升级：**

1. 先完整备份元数据库。V3 为前向迁移，仓库不提供回滚脚本。
2. 使用 1.5.0 的分发包或镜像直接启动，Flyway 会按版本顺序应用 `V3__v1_5_0.sql`。
3. V3 只做两件事：给 `yak_ops_modeling_model_field` 增加可空列 `aggregate_type`（取值 `SUM` / `COUNT` / `AVG` / `MAX` / `MIN`，含值 `CHECK`）；给 `yak_ops_modeling_model` 增加 DWS 与 ADS 的归属 `CHECK`。
4. 既有 DWD / DIM 数据行不受影响：新增归属约束对非 DWS / ADS 类型恒为真，可空列无需回填。
5. 不要手工修改 `flyway_schema_history`，也不要用 `flyway repair` 跳过校验。
6. 需要回退到 v1.4.0 时，还原升级前的备份；不能假设旧版本可以直接读取已升级的库。

**全新安装：** 使用空的 MySQL 元数据库启动即可，`V1__baseline.sql`、`V2__v1_4_0.sql` 与 `V3__v1_5_0.sql` 会依次执行。

## Known Limitations

- **物理发布未实现。** 本版只产出逻辑模型，不向引擎建表；汇总表与应用表同样不生成物理 DDL。
- **没有指标模块。** 聚合方式只能手工指定，字段不提供「从指标导入」，汇总表与应用表也不从原子指标派生。
- **聚合函数只有五种基础形式。** `COUNT DISTINCT` 等带修饰符的聚合不在范围内；聚合粒度由维度列决定，本版不提供额外的粒度声明。
- **应用表的归档分类与数据集市无父子关系。** 后端沿用应用层维度表的既有校验，分类仅为归档用途，界面已就此提示。
- **批量录入的 DDL 解析只覆盖标准字段定义子集。** 与 v1.4.0 相同：`DEFAULT` 表达式被忽略，表级子句直接跳过，无法映射的列保留在字段列表中标注待补全。
- **跨工作空间访问数据源 Catalog 返回 404。** 为防资源枚举，越权访问统一按「不存在」处理。
- **前端缺少自动化交互测试。** 页面逻辑由类型检查、静态检查与纯函数单测覆盖，异步交互未做浏览器实跑。
