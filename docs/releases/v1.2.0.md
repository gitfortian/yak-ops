# Yak Ops v1.2.0

**Released:** 2026-10-07

## Overview

本版聚焦 Schema 感知、字段映射、目标表自动创建，以及减少用户手工配置的运行参数与智能重试策略。

## Highlights

- **自动建表：** 读取来源表结构，规划 MySQL、PostgreSQL、Oracle 的目标 DDL，缺失目标表时可显式创建。
- **字段映射：** 支持选择、重排和重命名字段，映射随 Execution 定义快照冻结。
- **运行参数内化：** 自动规划离线运行参数；对明确的瞬时错误采用有边界的智能重试。

## New Features

- Schema：Catalog 元信息读取、逻辑类型归一、复合主键顺序、目标原生类型规划、表结构兼容性检查。
- DDL：可预览目标 CREATE TABLE 及表/字段注释；运行前重新读取目标 Catalog 校验。
- Mapping：字段子集、重排、改名；实时 MySQL CDC 支持主键字段重命名后的快照和增量写入。
- Runtime：离线新任务默认使用后端 `AUTO` 策略计算有效参数，并冻结到 Execution Snapshot。
- Retry：新任务默认 `SMART`，`maxAttempts=3`、初始 Backoff 15 秒，仅针对明确瞬时错误；`RETRY_WAITING` 的下一次重试时间持久化。
- 实时列表：启动、停止、重新启动的状态语义与操作入口。

## Improvements

- 不再要求普通用户管理 `fetchSize`、批次大小、Split 并行度等底层调优项。
- 历史固定 Runtime/Retry 配置在没有新策略字段时继续按 `FIXED` 解释，避免升级覆盖既有行为。
- APPEND/OVERWRITE 在运行已开始后不进行不安全的自动重放；UPSERT/Realtime CHANGELOG 对明确瞬时失败才允许重试。

## Compatibility

- 保留 v1.1.0 的 Task/Workspace/CDC State 身份及 at-least-once 语义。
- 目标表自动创建适用于当时文档覆盖的 MySQL、PostgreSQL、Oracle 类型规划。
- 旧 Task 默认 `autoCreateTable=false`；`mapping_config=NULL` 表示同名隐式映射；旧运行/重试设置保持 `FIXED`。

## Upgrade Guide

从原有 v1.0.0/v1.1.0 的迁移链向前应用 `V3__v1_2_0.sql`，新增 `auto_create_table` 和 `mapping_config`。已发布的 V1/V2 SQL 不应修改。升级前备份元数据库和 CDC 状态；自动建表只创建缺失的目标表，不会对现有表自动 ALTER、DROP 或执行 DDL 同步。

## Known Limitations

- 不支持多表任务、自动 DDL Evolution、Transform/Expression/Custom SQL 映射。
- 不支持 PostgreSQL CDC 等新增 CDC Source、分布式 Runtime/HA 或 exactly-once。
- 不提供底层 Runtime/Retry 策略 UI、实时完整 Trace 或长期运行 Watchdog。
- 不声明通用 YakFlow Checkpoint 的跨进程恢复能力。
