# Yak Ops v1.8.0

**Released:** 2026-10-25

本文件记录 1.8.0 版本的既定产品行为。本仓库尚未为该版本创建 Git Tag 或 GitHub Release，发布状态见 [Releases 索引](README.md)；下文 Downloads 与 Compatibility 描述的是当前实际可获取的内容。

## Overview

本版把「数据指标」立为数据建模下的独立模块：时间周期、修饰词、原子指标、派生指标、复合指标五类记录共用一套 Workspace 作用域与编码规则。派生指标没有自己的名字——它的编码与名称由时间周期、修饰词与原子指标组合而成并落库，相同组成必然得到同一条指标，重复创建被直接拒绝。复合指标保存算术表达式与解析出的派生指标引用，只做设计时记录，不求值。汇总与应用表的字段可以标注「从哪个派生指标导入」，该链接受删除保护。数据库新增一处前向迁移。

## Highlights

- **五类指标统一管理：** 时间周期与修饰词是受治理的词典（修饰词必须锚定一个数据域），原子指标、派生指标、复合指标是带负责人的记录；全部按种类分页签管理，不再依附标准分类树（[YOIP-14](../yoips/YOIP-14-data-modeling-metrics.md)）。
- **派生指标组合即唯一性：** 组合编码形如 `<周期>_<修饰词...>_<原子指标>`（最多 64 位），组合名称按同序拼接；服务端组合并存储，相同组成的第二次创建返回 `19302`，另一个 Workspace 可以合法使用同样的组成。
- **原子指标带统计口径：** 业务过程、逻辑类型与聚合方式（求和/计数/平均/最大/最小）在保存时即校验匹配——求和与平均只允许 BIGINT、DECIMAL，一条不可能被任何合法字段引用的指标无法被创建。
- **复合指标是纯表达式：** 只接受四则运算、括号、数字与派生指标编码；保存时解析并存储全部引用，引用了不存在编码或语法非法的表达式被拒绝（`19307`）。平台从不执行该表达式。
- **删除前给出依赖清单：** 每类指标都能列出「谁在用我」——派生指标被复合指标或模型字段引用、原子指标/周期/修饰词被派生指标组成引用时，删除被拒绝（`19308`）并展示具体依赖；派生指标删除时其修饰词链接级联清理。
- **汇总/应用表字段可标注指标来源：** 模型字段新增可选的派生指标链接，仅汇总（DWS）与应用（ADS）字段接受；链接是标注性的，不改变字段的类型与属性，但被引用的指标不能删除。
- **数据库一处前向迁移：** `V6__v1_8_0.sql` 新增 7 张指标表，并给模型字段表增加一个可空列 `metric_id`。

## New Features

**时间周期与修饰词**

- 时间周期是 Workspace 内的平面词典：中文名称、英文编码（小写字母开头，仅小写字母、数字、下划线，最多 64 位）与说明；编码在 Workspace 内唯一，并作为派生指标组合编码的第一段。
- 修饰词必须锚定本 Workspace 的一个数据域；数据域删除时被锚定的修饰词会先拒绝域删除。
- 两类词典均提供编码可用性检查（`GET …/codes/availability`）与依赖查询（`GET …/{id}/references`）。

**原子指标**

- 由所属业务过程、编码、中文名称、逻辑类型、聚合方式、可选度量单位与负责人组成；聚合方式与逻辑类型的匹配矩阵与模型字段口径一致，不匹配返回 `19305`。
- 负责人缺省为创建者；指定的负责人必须是当前 Workspace 的有效成员，否则返回 `19304`。
- 可选绑定度量单位做标注；度量单位只说明量纲，不改变指标类型。

**派生指标**

- 提交内容只有组成部分（原子指标、时间周期、有序修饰词）与说明；编码与名称由服务端组合生成并存储，用户不可自拟。
- 组合结果超过编码 64 位或名称 128 位上限时返回 `19306`；同一修饰词出现两次同样被拒绝。
- 编辑组成部分会重新组合并整体替换修饰词链接；修改后的组合若与其他指标冲突，整个编辑被拒绝。
- 编辑时间周期、修饰词或原子指标的编码或名称时，所有引用它的派生指标在同一事务内重新组合并更新（组合编码与名称随之变化）；重算结果超出列宽限制时，该部件编辑被拒绝，派生指标保持原值。
- 组合可用性检查（`GET /derived-metrics/codes/availability`）按同一组合算法回答，供界面在保存前提示。

**复合指标**

- 保存提交的原始表达式文本（最多 2048 字符）与解析出的引用清单；引用在首次出现顺序上去重。
- 表达式引用只允许派生指标，引用图因此保持两层、无环，无需环检测。
- 删除复合指标不做引用检查——没有任何资产能引用一个复合指标。

**模型字段指标链接**

- 汇总与应用表的字段可携带可选的 `metricId` 指向本 Workspace 的派生指标；明细表与维度表携带该字段会被 `19506`（`INVALID_FIELD`）拒绝。
- 未知指标返回 `10010`；链接只做标注，不覆盖字段的编码、类型、精度或非空。
- 被字段引用的派生指标删除时被外键拒绝，删除对话框会列出引用它的表与字段。

**REST 端点（均为增量）**

- `GET|POST|PUT|DELETE /api/v1/data-modeling/metrics/time-periods[/{id}]`、`…/codes/availability`、`…/{id}/references`。
- `…/modifiers…`（分页支持 `domainId` 过滤）、`…/atomic-metrics…`（分页支持 `processId` 过滤）、`…/composite-metrics…` 形状一致。
- `GET|POST|PUT|DELETE …/derived-metrics[/{id}]`；可用性检查参数为 `atomicMetricId`、`periodId`、`modifierIds` 与可选 `excludeId`。

**前端**

- 新增「数据指标」页面：五类页签共享刷新与搜索；派生指标弹窗实时预览组合编码与名称、按提交顺序维护修饰词并即时提示组合冲突；复合指标弹窗即时解析表达式引用；删除对话框在删除前展示依赖清单。

## Improvements

- 五类指标共用一份 `MetricCatalog`：Workspace 成员授权、编码与名称规则、关键字转义、分页边界只定义一次，不会出现「某类指标校验更松」。
- 新增错误码 `19301`–`19308`（编码非法、编码重复、乐观冲突、负责人无效、原子指标口径不匹配、派生指标组成无效、复合表达式无效、被引用不可删除），HTTP 状态分别为 400、409、409、400、400、400、400、409。
- 模型字段的读取接口回带 `metricId`、`metricEnCode`、`metricCnName` 三个字段，模型字段表查询左联派生指标取显示值。
- 集成测试注册表新增 `modeling` 套件的 `MetricDatabaseIT` 与端到端套件的 `MetricsIT`，两者在 CI 的真实 MySQL 上运行。

## Bug Fixes

- **模型字段聚合类型缺失时发布校验报错不明确。** 补齐了物理发布测试夹具的默认值构造（无用户可见行为变化）。

## Breaking Changes

- 无。本版全部为增量能力：新增的表、端点与错误码不影响既有请求；`yak_ops_modeling_model_field.metric_id` 为可空新列，既有行无需回填。

## Compatibility

- 运行要求 Java 21；Yak Ops 元数据库使用 MySQL 8。
- 升级路径覆盖 v1.7.0（即含 `V1__baseline.sql` 到 `V5__v1_7_0.sql` 的元数据库）。
- `V6__v1_8_0.sql` 新增 7 张表；对既有表的唯一改动是给模型字段表增加可空的 `metric_id` 列、一个索引与一个 RESTRICT 外键，既有行无需任何回填。
- 修饰词锚定数据域、原子指标锚定业务过程、原子指标可选锚定度量单位，均为 RESTRICT 外键；既有数据不受影响。
- 未验证的数据库版本、数据规模与部署组合不能作为正式承诺；可运行范围以本仓库 `master` 上 1.8.0 版本元数据对应的提交为准。本版尚未执行 Release Gate，也没有对应的 Git Tag、分发包与镜像。
- 模型字段的指标链接仅由应用校验接受范围；直接写库绕过应用时数据库只保证外键存在性，不限制模型类型。

## Upgrade Guide

**从 v1.7.0 升级：**

1. 先完整备份元数据库。V6 为前向迁移，仓库不提供回滚脚本。
2. 使用 1.8.0 的分发包或镜像直接启动，Flyway 会按版本顺序应用 `V6__v1_8_0.sql`。
3. V6 做两件事：新建时间周期、修饰词、原子指标、派生指标、派生指标修饰词链接、复合指标、复合指标引用七张表；给模型字段表增加可空的 `metric_id` 与外键。
4. 升级后既有行为不变：没有任何既有页面或接口读取指标表；模型字段不携带 `metricId` 时一切照旧。
5. 不要手工修改 `flyway_schema_history`，也不要用 `flyway repair` 跳过校验。
6. 需要回退到 v1.7.0 时，还原升级前的备份；不能假设旧版本可以直接读取已升级的库。

**全新安装：** 使用空的 MySQL 元数据库启动即可，`V1__baseline.sql` 到 `V6__v1_8_0.sql` 会依次执行。

## Known Limitations

- **表达式是设计时记录。** 复合指标不被任何计算引擎求值，也不参与调度；把它接入计算属于后续版本的范围。
- **复合指标只能引用派生指标。** 不能引用原子指标或另一个复合指标；两层引用图是本版的有意约束。
- **派生指标不能脱离组成存在。** 编码与名称只能来自组合，不能手工指定；需要独立命名的口径请使用复合指标或字段标准表达。
- **模型字段与指标的链接是标注。** 不校验字段类型与指标口径一致，也不在发布阶段改写物理列；「从指标导入」作为编辑动作批量播种字段属性的能力依赖模型编辑器的后续收尾（仓库 Issue #29），本版先落库契约与删除保护。
- **原子指标负责人不做展示名解析。** 列表只返回 `ownerId`，不像字段标准那样回填成员姓名。
- **前端缺少自动化交互测试。** 新增页面由类型检查、静态检查与组合/表达式纯模块的单元测试覆盖，浏览器实跑未纳入本版。
