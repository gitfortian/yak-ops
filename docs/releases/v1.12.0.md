## Overview

v1.12.0 引入数据资产治理（FYOIP-16）的后端能力：平台开始对工作空间的数据资产做定期体检——四条内置规则扫描数据地图表与已发布任务，把"无负责人、缺描述、连续失败、运行过慢"沉淀为可指派、可忽略、可回归的治理问题，并给出 DEV / COMPUTE 两个维度的健康分与趋势。本版本只包含 REST API 与调度执行，不含控制台页面。

## Highlights

- **治理扫描（V10）**：新增扫描运行、规则结果、治理问题、问题事件与健康快照五张表；规则引擎代码内置，首轮交付四条规则。
- **四条内置规则**：数据地图表无负责人（HIGH）、表缺描述（LOW）、任务连续 3 次以上调度失败（HIGH）、近 7 天调度实例平均耗时超 7200 秒（MEDIUM）；每条规则都会影响健康分。
- **问题生命周期**：每个 `(规则, 目标)` 只有一个活跃问题，重新检测复用同一行；支持指派（OPEN→HANDLING）、1–90 天忽略、人工解决与重开，完整扫描不再发现目标时自动收敛解决。
- **健康分**：DEV / COMPUTE 独立计分，只统计 OPEN 与 HANDLING 的问题；无合格基数的维度显示 N/A 而非 100；每日快照支撑 90 天趋势。
- **扫描纪律**：每工作空间同时最多一个进行中扫描（唯一索引保证）；数据地图采集进行中时扫描显式 `SKIPPED`（`DATA_MAP_BUSY`），绝不把部分结果当完整结果。

## New Features

- **治理 API**：`/api/v1/governance` 提供总览（`overview`）、健康分与趋势（`health`）、规则清单（`rules`）、问题列表/详情/事件（`issues`、`issues/{id}`、`issues/{id}/events`）、问题操作（`assign`、`resolve`、`reopen`、`ignore`、`unignore`）与扫描（`scans` 列表/手动发起/详情）。
- **扫描触发**：每日 UTC 0 点定时扫描（`yak.governance.scan.cron`，可配置）加工作空间成员手动发起；应用启动时有恢复清扫，把进程中断遗留的 `RUNNING` 扫描收敛为终态。
- **扫描完整性语义**：所有规则完成才算 `SUCCEEDED`；任一规则失败为 `PARTIAL`；全部无法运行为 `FAILED`；因数据地图采集占用而未执行为 `SKIPPED`。失败或部分的规则不关闭任何问题。
- **问题证据**：每个问题记录数值化证据（观测值、阈值、样本数、窗口天数）与稳定规则码；忽略窗口到期的问题在下次扫描时自动回到 OPEN 并重新参与计分。
- **错误码**：19801–19806（批量上限、非法状态、非法负责人、忽略窗口越界、扫描冲突、日期区间越界）。
- **保留策略**：扫描运行、规则结果与健康快照保留 90 天；已解决问题及其事件在解决后保留 180 天；清理分块执行，不触碰 OPEN / HANDLING / IGNORED 问题。

## Improvements

- 本版本为治理能力的首个交付，无对既有功能的独立改善。

## Bug Fixes

- 本版本无独立缺陷修复。

## Breaking Changes

- 无。本版本只新增表、接口与后台调度，不修改既有行为与数据。

## Compatibility

- 数据库：V10 仅新增五张 `yak_ops_governance_*` 表与索引，不修改既有表和行；沿用 64 位应用侧生成 ID、InnoDB 与 `utf8mb4_unicode_ci` 约定，无 JSON 列。
- API：既有接口不受影响；治理接口全部为新增。
- 调度：扫描调度依赖应用内 `@Scheduled`，与任务调度一致的"单节点、应用内调度"边界。
- 前端：本版本不包含控制台界面，治理能力仅通过 REST API 提供。

## Upgrade Guide

1. 备份元数据库。V10 迁移是本版唯一的结构变更，备份是回退到 1.11.0 镜像时的可靠手段。
2. 用 1.12.0 的分发包或镜像替换旧版本，启动时 Flyway 自动应用 `V10__v1_12_0.sql`；该脚本只建表和索引，不需要停机维护窗口。
3. 升级后无需数据修复：首次扫描会从零建立问题与快照；首次快照落地前健康趋势为空属预期行为。
4. 回退到 1.11.0 时，库中会多出五张表与一条 V10 迁移记录；本仓库未验证旧版本对更高版本迁移记录的校验行为，回退应同时恢复备份。

## Known Limitations

- 控制台页面（治理总览、问题列表、数据地图"治理"页签）尚未包含在本版本，将通过后续 PR 交付；期间只能通过 API 使用治理能力。
- 规则清单代码内置、只读：不支持规则启停、阈值配置与自定义 SQL；未达标即扣分，无 warn-only 模式。
- 任务类规则只评估 `SCHEDULE` 触发的实例，手动与工作流触发不参与；当前定义版本调度实例不足 3 次的任务不会被判定。
- 扫描为单节点应用内调度，多实例部署时到期扫描在持有执行的节点上运行；本版本未做集群执行声明。
- 快照按 DEV / COMPUTE 两维展示卡片与趋势；未引入雷达图（需至少三个维度）。
- 查询区间上限 90 天，与快照保留策略一致。
