# Yak Ops v1.7.0

**Released:** 2026-10-25

本文件记录 1.7.0 版本的既定产品行为。本仓库尚未为该版本创建 Git Tag 或 GitHub Release，发布状态见 [Releases 索引](README.md)；下文 Downloads 与 Compatibility 描述的是当前实际可获取的内容。

## Overview

本版把「数据标准」从只有字段标准一种，补成完整的四类：字段标准、标准代码（码表）、度量单位、命名词典，并让它们互相引用。字段标准新增父标准、业务预设值、码表引用与度量单位引用；删除前的引用检查不再是一个占位状态，而是返回具体依赖对象。数仓分层新增可启用的表名命名规则，把命名词典与业务过程编码真正约束到表名后缀上。数据库仍只有一处前向迁移。

## Highlights

- **四类标准共用一棵分类树：** 节点分为「目录」与「标准集」，标准集声明自己存放字段标准还是标准代码，并且只能放该种类的记录；目录下两种都可以（[FYOIP-13](../yoips/FYOIP-13-data-modeling-complete-data-standards.md)）。
- **字段标准补四项属性：** 父标准（最多 8 层、拒绝自指与成环）、业务预设值、码表引用、度量单位引用；后两者只约束取值范围与标注，不改变字段类型。
- **引用查询返回真实依赖：** 字段标准、标准代码、度量单位、命名词典都能列出「谁在用我」，删除被引用的记录被直接拒绝并展示依赖清单。
- **分层命名规则可启用：** 启用后该分层下明细表与汇总表的表名后缀必须是「词根_业务过程编码」，可再跟一个「_限定词」；词根取自命名词典，维度表与应用表豁免。
- **DECIMAL 标准必须写全精度：** 字段标准保存时即要求完整的「总位数,小数位」，避免出现「设计得出来、永远发布不出去」的标准。
- **数据库仍只有一处前向迁移：** `V5__v1_7_0.sql` 新增 4 张表并给既有表增加可空列或带默认值的列，唯二的结构调整是一个唯一键的替换与一个编码列的排序规则收紧。

## New Features

**标准分类节点**

- 新建节点时选择「目录」或「标准集」；标准集必须声明存放字段标准还是标准代码。
- 标准集的种类在它还有记录时被锁定，接口返回 `19111`，界面在种类下拉框上直接说明原因；把记录清空后可以重新切换。
- 目录不接受种类声明，标准集不接受另一种类的记录，两种情况都以参数错误拒绝。

**标准代码（码表）**

- 码表由编码、中英文名称、说明与一组有序值组成，值的顺序取提交顺序，序号从 1 开始。
- 值列表是整体替换：任一值编码为空、超过 64 位或与同表内其它值重复时，整份提交被拒绝（`19110`），不会留下改了一半的列表。
- 删除码表时，被字段标准或模型字段引用则拒绝删除并列出依赖。

**度量单位**

- 单位类型是封闭的五类：货币、量词、比率、排名、时间；编码在 Workspace 内唯一。
- 度量单位是平面清单，不挂在分类树下，因此只按类型与关键字检索。

**命名词典**

- 词典是 Workspace 级的平面清单，编码即「词根」，是分层命名规则唯一认可的取值来源。
- 被模型记录为命名来源的词根不能删除，删除请求会返回依赖清单。

**字段标准扩展**

- 父标准：可空，必须同 Workspace、不能是自身、不能成环、整条链最多 8 层（含当前记录）；父标准只表达「细化关系」，不继承属性。
- 业务预设值：最多 2048 字符，仅作为业务含义保存，**不**生成建表语句的 `DEFAULT` 子句。
- 码表引用与度量单位引用：保存时校验存在性；码表约束取值范围，度量单位只做标注。
- 字段标准的编码唯一性从「全局唯一」放宽为「Workspace 内唯一」，与其它建模表的作用域一致。

**分层命名规则**

- 每个分层有一个开关。启用时，该分层下 DWD 与 DWS 模型的表名后缀必须形如 `<词根>_<业务过程编码>`，可再接一个 `_<限定词>`，用于让 `trade_order_1d` 与 `trade_order_1h` 并存。
- 后缀总长上限 41 个字符；启用前先校验该分层下现有模型的过程编码能否与词典中最短词根组合成形，不能则不允启用。
- 启用时接口返回当前不符合规则的模型清单；存在不符合项时必须显式确认才允许启用，确认只表示「已知悉」，不会给这些模型任何豁免——它们改名为合规后缀之前无法再次保存。
- 匹配成功的模型会记录它使用的词根；词根不参与表名拼接，表名仍由用户输入，避免同一分层只能建一张表。
- 模型保存时若后缀不合规返回 `19513`，界面把该错误定位到表名字段。

**REST 端点（均为增量）**

- `GET|POST /api/v1/data-modeling/data-standards/lookups[/{id}]`、`/categories/{categoryId}/lookups`、`/lookups/{id}`、`/lookups/codes/availability`、`/lookups/{id}/references`。
- `GET|POST /api/v1/data-modeling/data-standards/measure-units…` 与 `…/naming-entries…`，形状与码表一致（无分类归属）。
- `GET|PUT /api/v1/data-modeling/warehouse-planning/layers/{id}/naming-rule` 读取或更新一个分层的命名规则。
- `GET /fields/{id}/references` 的响应新增 `items`，`referenced` 与 `count` 由它派生。

## Improvements

- 四类标准共用一份 `StandardCatalog`：Workspace 授权、目录锁、编码与名称规则、分页边界只定义一次，不会出现「某类标准校验更松」。
- 新增错误码：`19109`（父标准非法）、`19110`（码表值非法）、`19111`（标准集种类已锁定）、`19208`（命名规则无法启用）、`19513`（表名不符合命名规则），HTTP 状态分别为 400、400、409、422、400。
- 模型字段绑定字段标准后，编码、中文名、类型、长度精度与非空改为**以标准为准**，提交值被忽略；码表只在没有绑定标准时补足编码与中文名。这是本版唯一的语义变更，见 Breaking Changes。
- 引用检查从「未启用」占位改为按能力真实查询：模型字段引用字段标准、字段标准引用码表/单位、模型引用词根三条路径分别聚合。
- 前端数据标准页按种类分页签，码表编辑支持增删值并整体提交；字段标准编辑器把「长度/精度」拆成按类型变化的两组输入，`DECIMAL` 用「总位数 + 小数位」两个数字表达。
- 数仓分层面板新增「命名规则」入口，展示违规模型清单与 41 字符上限说明。

## Bug Fixes

- **DECIMAL 字段标准可以不带精度保存。** 这类标准能建出来，但物理发布一定会被 `PhysicalTypes` 拒绝，形成永远发不出去的标准；现在保存阶段即校验完整精度对，与发布阶段的判定一致。
- **编码唯一性作用域错误。** 字段标准的唯一键原本只有 `en_code`，两个 Workspace 不能各自定义 `member_id`；已替换为 `(workspace_id, en_code)`。
- **标准集种类静默失效。** 在标准集下创建另一类记录此前不会被拦截，现在按节点声明的种类拒绝。

## Breaking Changes

- **模型字段绑定标准后的取值优先级变了。** 之前以请求提交的编码、名称、类型、长度与非空为准，标准只做存在性校验；现在这五项由标准决定，请求里的对应字段被忽略。依赖「绑了标准但仍可自由改类型」的调用方会观察到行为变化。码表与度量单位仍为可选标注，不是权威来源。
- **字段标准编码唯一性范围收窄到 Workspace。** 原本全局唯一，因此放宽不会与既有数据冲突；但依赖「跨 Workspace 编码全局不可重复」这一旧约束的集成需要调整预期。
- `yak_ops_standard_field.en_code` 的排序规则收紧为 `ascii_bin`，与非 ASCII 编码相关的历史数据需要先自查（正常编码规则本就不允许非 ASCII）。

## Compatibility

- 运行要求 Java 21；Yak Ops 元数据库使用 MySQL 8。
- 升级路径覆盖 v1.6.0（即含 `V1__baseline.sql` 到 `V4__v1_6_0.sql` 的元数据库）。
- `V5__v1_7_0.sql` 新增的列全部可空或带默认值（`node_type` 默认 `DIRECTORY`、`naming_rule_enabled` 默认 `0`），既有行无需回填即可满足约束；`naming_root_word_id` 只在启用命名规则时写入。
- 既有分类节点升级后全部是「目录」，可以继续存放字段标准与新建的码表；需要锁种类时再改成标准集。
- 未验证的数据库版本、数据规模与部署组合不能作为正式承诺；可运行范围以本仓库 `master` 上 1.7.0 版本元数据对应的提交为准。本版尚未执行 Release Gate，也没有对应的 Git Tag、分发包与镜像。
- 本版未执行浏览器端自动化 E2E 或跨浏览器验收，前端交互的验证边界见 Known Limitations。

## Upgrade Guide

**从 v1.6.0 升级：**

1. 先完整备份元数据库。V5 为前向迁移，仓库不提供回滚脚本。
2. 使用 1.7.0 的分发包或镜像直接启动，Flyway 会按版本顺序应用 `V5__v1_7_0.sql`。
3. V5 做四件事：给标准分类表加 `node_type` 与 `standard_kind`；新建码表、码表值、度量单位、命名词典四张表；给字段标准表加 `default_value` / `parent_standard_id` / `lookup_id` / `measure_unit_id` 与三个外键，并替换编码唯一键；给模型字段表加码表与单位引用、给模型表加命名词根、给分层表加命名规则开关。
4. 升级前自查：同一 Workspace 内不应存在重复的字段标准编码（旧约束是全局唯一，正常数据不会触发）。
5. 升级后既有行为不变：没有启用命名规则的分层不校验表名，没有绑定码表/单位的字段标准照旧保存。
6. 不要手工修改 `flyway_schema_history`，也不要用 `flyway repair` 跳过校验。
7. 需要回退到 v1.6.0 时，还原升级前的备份；不能假设旧版本可以直接读取已升级的库。

**全新安装：** 使用空的 MySQL 元数据库启动即可，`V1__baseline.sql` 到 `V5__v1_7_0.sql` 会依次执行。

## Known Limitations

- **父标准只表达关系。** 不继承类型、长度或非空，也没有「标准集」层面的强制唯一；跨标准的校验规则不在本版范围。
- **码表不进入建表语句。** 绑定码表只记录引用关系，不生成 `CHECK` 或外键，也不写入字段注释。
- **命名规则只覆盖 DWD 与 DWS。** 维度表与应用表豁免，因为它们的表名不承载业务过程。
- **规则启用前的不合规模型需要人工改名。** 系统不会自动重命名，也不会阻断它们的读取，只阻断再次保存。
- **单个分层只有一个规则。** 不能按业务过程分别配置不同的词根集合，也不能配置除「词根 + 过程 + 单一限定词」之外的形式。
- **批量录入与从表导入不带这几项新属性。** 父标准、码表、单位与预设值都需在编辑器里手工指定。
- **模型编辑器的两处选择控件随后续前端版本补齐。** 本版接口契约已就绪（分层选项带 `namingRuleEnabled`、模型字段接受 `lookupId` 与 `measureUnitId`），但规则启用后模型弹窗仍是自由输入后缀、字段编辑器暂无码表与单位下拉；跟进任务记录在仓库 Issue #29，将在专项前端 PR 中交付。
- **前端缺少自动化交互测试。** 页面逻辑由类型检查、静态检查与既有单测覆盖，新增的页签、码表值编辑与命名规则对话框未做浏览器实跑。
