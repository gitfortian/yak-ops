## Overview

v1.14.0 用「标签键 — 标签值 — 绑定」的两级字典替换扁平标签（FYOIP-19）：键是维度（如「部门」），值是键下的取值（如「电商」），绑定把取值挂到数据地图资产上。筛选从「选一个标签」升级为「同键取值取并集、不同键取交集」，删除不再静默剥离资产引用，字典的增删改收敛到工作空间管理员。既有扁平标签在升级时整体迁移为一个 `legacy` 键下的取值，不丢数据、不改名。

## Highlights

- **两级字典**：标签键名称工作空间内唯一（1–64 字符），标签值在键内唯一（1–128 字符），大小写不敏感；资产可以同时持有同一个键的多个取值（如 `部门 = 电商` 且 `部门 = 零售`）。
- **多维筛选**：`GET /api/v1/data-map/tables` 的 `tagId` 参数替换为可重复的 `tagValueIds`；同一键的取值取并集，不同键取交集，`部门 IN (电商, 零售) AND 敏感度 = PII` 是一条两子句的筛选。
- **删除保护**：仍被资产引用的标签值或标签键拒绝删除（`TAG_IN_USE`），由 `ON DELETE RESTRICT` 约束保证而非应用层预检；删除资产会级联清理其绑定，字典行保留。
- **权限分级**：标签键与取值的创建、重命名、删除要求工作空间 `OWNER` 或 `ADMIN`（`TAG_WRITE_FORBIDDEN`）；任何成员都可以替换单个资产的标签或执行批量绑定。治理导航新增一级入口「数据治理 > 标签管理」。
- **数据迁移**：升级时每个有标签的工作空间生成一个 `legacy` 键，旧标签名成为其取值，旧绑定按原 `create_by` 复制；派生 ID 由工作空间 ID 确定性生成，恢复备份后重新迁移得到同一身份。

## New Features

- **标签管理控制台**（`/data-governance/tags`）：左栏标签键、右栏取值与引用资产数，支持重命名、删除与「批量绑定」；批量绑定从资产目录选择最多 100 张资产、20 个取值，一次事务完成添加或移除。
- **标签字典 API**：`/api/v1/tags` 提供键的增删改查（`GET/POST /keys`、`PUT/DELETE /keys/{keyId}`）、取值的增删改（`POST /keys/{keyId}/values`、`PUT/DELETE /values/{valueId}`）、单资产替换（`PUT /tables/{tableId}`）与批量绑定（`POST /bindings/batch`）。
- **资产标签编辑**：资产详情页的标签弹窗改为按键分组的选择器，只绑定/解绑既有取值，并提供跳转标签管理的入口。
- **错误码**：19901–19907（重复键名、重复值名、引用中、单资产超 20 个取值、单键超 200 个取值、非管理员写字典、批量超限）。

## Improvements

- 目录资产列表的标签列最多展示 3 个取值，超出折叠为 `+N`；资产详情按键分组展示全部取值。
- 标签字典的读取收敛为单语句投影（绑定连接键与值），目录列表与资产详情共用一次查询。
- 批量绑定使用 `INSERT IGNORE` 幂等写入，与其他事务并发插入同一对绑定时不再报重复键错误。

## Bug Fixes

- 取值引用数的投影列名为 `tag_value_id`，而行类型属性是 `valueId`，MyBatis 自动映射因此把每个取值的 `valueId` 留空、全部计数折叠到同一个空键，字典页的引用数恒为 0；投影改为显式驼峰列别名后由 `TagDatabaseIT` 在真实 MySQL 上守住。

## Breaking Changes

- **删除语义变化**：删除标签不再把标签从资产上剥离；仍被引用的标签删除会失败并返回 `TAG_IN_USE`，需先解除引用。旧版「删除即静默解绑」的行为被约束取代。
- **接口下线**：`GET/POST /api/v1/data-map/tags`、`PUT/DELETE /api/v1/data-map/tags/{tagId}`、`PUT /api/v1/data-map/tables/{tableId}/tags` 随本版本移除，无别名、无双写窗口；前端同版本切换到 `/api/v1/tags`。
- **参数与响应变化**：`DataMapTableQueryDTO.tagId` 改为 `tagValueIds`（可重复）；目录响应中的 `DataMapTagVO`（`{id, name}`）替换为 `DataMapTagRefVO`（`{keyId, keyName, valueId, valueName}`）。旧客户端继续发送 `tagId` 会被 Spring 忽略，筛选静默失效，因此前后端必须同版本发布。
- **数据库结构**：`V12__v1_14_0.sql` 新建 `yak_ops_tag_key`、`yak_ops_tag_value`、`yak_ops_data_map_table_tag_value` 三张表，迁移旧数据后删除 `yak_ops_data_map_tag` 与 `yak_ops_data_map_table_tag`。无降级路径，回退需恢复升级前备份。

## Compatibility

- 数据库：MySQL 8（InnoDB、`utf8mb4_unicode_ci`），沿用 64 位应用侧生成 ID 与 `DATETIME(3)` 约定；迁移派生 ID 为 `tklg`/`tvlgb` 前缀加 32 位十六进制，与 `IdUtils.nextId()` 的数字 ID 不会碰撞。
- 运行环境：JDK 21；单节点应用内调度边界不变，无集群执行声明。
- API：`/api/v1/tags` 为新增；数据地图其余接口的请求与响应除标签筛选外不变。
- 前端：React 单页应用，标签控制台为数据治理产品线下的一级入口。

## Upgrade Guide

1. 备份元数据库。V12 迁移会删除两张旧表，备份是回退到 1.13.0 镜像时的可靠手段。
2. 用 1.14.0 的分发包或镜像替换旧版本，启动时 Flyway 自动应用 `V12__v1_14_0.sql`；迁移把既有标签迁入 `legacy` 键，无需人工数据修复。
3. 升级后到「数据治理 > 标签管理」检查 `legacy` 键：按需把资产改绑到正式键，再由管理员删除 `legacy`；本版本不提供自动合并。
4. 若工作空间此前没有任何标签，不会生成 `legacy` 键，目录与资产行为不变。
5. 回退到 1.13.0 时需同时恢复备份；旧表不会被任何脚本重建。

## Known Limitations

- 标签只能挂到数据地图表，不支持列、模型、指标等其他资产类型，也不支持多态目标；泛化绑定表需要独立提案与迁移。
- 单个键最多 200 个取值、单个资产最多 20 个取值、单次批量最多 100 张资产与 1000 条绑定，超出返回对应错误码；取值列表不分页。
- 不支持预设标签、标签分组与层级、合并工具、审批流、类型化取值与基于标签的评分；`legacy` 键可能与正式键长期共存。
- 删除仅有 `create_by`/`update_by` 审计列与 INFO 日志，没有独立标签事件表。
- 标签控制台界面随本版本首次交付，未经真实浏览器交互验收（Playwright 套件按发布门禁执行）。
