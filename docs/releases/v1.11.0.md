## Overview

v1.11.0 把元数据采集从"按次手动提交"升级为可调度的**采集任务**：任务持有名称、数据源命名空间、负责人、手动或 Cron 触发方式与排除规则，运行历史仍逐次记录并标注来源任务。控制台的采集入口同步改为任务列表与全页编辑器；数据地图与数据建模页面统一到共享组件和语义 token。

## Highlights

- **采集任务（V9）**：新增 `yak_ops_data_map_crawl_task` 保存任务身份、生命周期与调度配置；运行表增加来源任务 `task_id` 与排除口径快照 `exclude_tables`。
- **定时调度**：只有 `RUNNING` 且 `CRON` 的任务会被调度，按持久化的 `next_fire_time` 触发；`DRAFT` 与 `OFFLINE` 不触发，`MANUAL` 只能手动发起。
- **任务编辑器**：基本信息、调度设置、高级设置 · 排除规则三段式；保存时可选择保存为草稿、保存或保存并上线。
- **预览能力**：编辑时预览接下来 3 个触发时间，或在数据源中预览正则会命中的表。
- **统一视觉**：数据地图与数据建模改用共享 Card、Badge、Alert、FieldRequiredMark、Checkbox 与语义颜色、字号 token。

## New Features

- **采集任务模型（V9）**：任务拥有数据源、库/模式命名空间、负责人、生命周期（`DRAFT`/`RUNNING`/`OFFLINE`）、触发方式（`MANUAL`/`CRON`）、Cron 表达式、下次触发时间与排除规则。运行仍写入 `yak_ops_data_map_crawl`，并记录来源任务；升级前的独立运行保留 `task_id = NULL`。
- **任务生命周期**：草稿不参与调度；上线（`RUNNING`）后可手动运行，Cron 任务同时进入调度；下线（`OFFLINE`）停止调度并保留配置与历史。只有草稿或已下线任务可以删除，否则返回 `CRAWL_TASK_DELETE_FORBIDDEN`（19717）。
- **手动运行**：仅上线任务可发起；同一任务已有进行中的运行时返回 `CRAWL_BUSY`，避免并行重复采集。
- **调度扫描**：应用内轮询（默认 30 秒，`yak.data-map.crawl-task-poll-interval-ms`），每批最多读取 20 个到期任务；先条件推进 `next_fire_time` 再提交运行，因此多实例重叠轮询对同一触发时刻最多提交一次；任务繁忙时跳过该次触发。
- **排除规则**：支持按表清单（上限 500 张）与 Java 正则两种方式；保存前可在数据源中预览命中表，提交运行时把当时的排除口径快照进运行行。被排除的表保持存活但不会重新读取字段，也不会因缺失判定被标记为已缺失；取消排除后下一次运行会重新同步。
- **任务 API**：`/api/v1/data-map/tasks` 提供列表、详情、创建、更新、状态切换、删除、立即运行与失败重试，以及 `preview-schedule`、`preview-exclude` 两个预览接口。
- **控制台**：元数据采集入口改为任务列表（状态、下次触发、最近运行、批量操作）与全页编辑器；旧的 `/data-governance/data-map/crawls` 地址重定向到任务列表。

## Improvements

- 数据地图与数据建模页面统一共享组件（Card、Badge、Alert、FieldRequiredMark、Checkbox）与语义颜色、字号 token，主题变量调整可同时作用于两个产品。
- 维度建模筛选栏改为 auto-fit 网格；此前 `Input` 与 `SelectTrigger` 内部自带 `w-full`，页面级 `w-56` 无法覆盖，导致控件逐行堆叠。

## Bug Fixes

- 维度建模筛选栏在宽屏下逐行堆叠、无法并排展示的问题（见 Improvements）。
- 本版无其它独立缺陷修复；v1.10.0 的采集能力（忽略表、失败重试、异常中断）随任务模型保留。

## Breaking Changes

- 控制台不再提供"直接提交一次采集"的入口：采集统一由任务发起，旧的采集记录列表被任务列表取代，`/data-governance/data-map/crawls` 重定向到任务列表。
- 后端保留 `POST /api/v1/data-map/crawls` 与 `GET /api/v1/data-map/crawls`，既有集成调用不受影响；新采集应通过任务接口发起，才能获得调度、排除快照与任务关联能力。

## Compatibility

- 数据库：V9 仅新增 `yak_ops_data_map_crawl_task` 表，并为 `yak_ops_data_map_crawl` 追加可空的 `task_id`、`exclude_tables` 列与索引、外键，不修改既有行。
- 历史运行：升级前的独立运行保留，`task_id` 为空，仍可通过 `GET /api/v1/data-map/crawls` 查询；控制台的任务列表不展示没有任务的历史运行。
- API：v1.10.0 的采集提交与查询接口保持；新增任务接口与两个预览接口。
- 前端：数据地图与数据建模的页面结构、文案与交互按任务模型更新，不改变资产目录与表详情的既有能力。

## Upgrade Guide

1. 备份元数据库。V9 迁移是本版唯一的结构变更，备份是回退到 1.10.0 镜像时的可靠手段。
2. 用 1.11.0 的分发包或镜像替换旧版本，启动时 Flyway 自动应用 `V9__v1_11_0.sql`；该脚本只建表、加列与索引，不需要停机维护窗口。
3. 升级后无需数据修复：既有运行保持原样，新建任务从第一次运行开始产生带 `task_id` 的记录。
4. 回退到 1.10.0 时，库中会多出一张表、两列与一条 V9 迁移记录；本仓库未验证旧版本对更高版本迁移记录的校验行为，回退应同时恢复备份。

## Known Limitations

- 调度是应用内轮询而非独立调度中心：多实例依靠条件更新避免同一触发时刻重复提交，但到期任务的启动仍发生在持有轮询的应用节点上。
- 排除表清单上限 500 张；正则采用 Java `find()` 语义，不支持逐表白名单。
- 每轮扫描最多提交 20 个到期任务，任务大量同时到期时按批逐步消化。
- 删除任务会同时删除其全部运行记录（外键级联），已采集的资产保留；运行中的任务必须先下线。
