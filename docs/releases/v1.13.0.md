**Released:** 2026-10-30

| 状态 | 发布说明已就绪，等待 Release Gate（本仓库 `master`） |
| 前一版本 | [v1.12.0](v1.12.0.md) |

## Overview

v1.13.0 将逻辑模型的物理发布从"只能建表、一键直达"升级为企业级发布闭环：数仓分层按开发/生产环境预绑定目标库，发布前生成物理表结构对比（新增列 / 类型变更 / 删除列）并预览最终 DDL，发布操作按差异自动判定为 CREATE、ALTER 或"无需发布"；删除列等破坏性变更必须显式勾选确认，每次发布的语句耗时、总耗时与执行日志（含失败堆栈）完整落库，可在发布历史中回查详情。本版本同时新增 Doris 数据源连接器，复用 MySQL 线协议、默认查询端口 9030。

## Highlights

- **环境绑定发布目标（V11）**：新增 `yak_ops_modeling_layer_target` 表，每个数仓分层（DWD/DWS 等）按 `DEVELOP` / `PROD` 环境预绑定数据源与目标库（工作空间 + 分层 + 环境唯一）。发布弹窗只选环境，数据源与目标库自动带出；未绑定直接给出明确错误（`TARGET_NOT_BOUND`）。
- **引擎感知的物理表属性**：按数据源类型动态渲染存储属性表单——Doris 支持分桶数（1–1024）、副本数（1–32）与 UNIQUE / DUPLICATE 数据模型；取值经校验后随模型落库（`physical_properties`），并在生成的 DDL 中透传（`UNIQUE/DUPLICATE KEY`、`DISTRIBUTED BY HASH ... BUCKETS`、`replication_num`）。
- **Schema Diff 引擎**：发布前拉取物理表实际结构与逻辑模型逐列对比（列名大小写不敏感，按类型族 / 精度 / 标度判定），发布操作三态：表不存在生成 `CREATE TABLE`，有漂移生成方言感知的 `ALTER TABLE`（MySQL/Doris 的 ADD/MODIFY/DROP、PostgreSQL 的 `ALTER COLUMN TYPE ... USING` 与 NOT NULL 调整、Oracle 的 `MODIFY`），结构一致提示"无需发布"。
- **防呆拦截**：发布弹窗以颜色区分变更（新增 / 类型变更 / 删除列）并展示最终 DDL；包含 `DROP COLUMN` 的 ALTER 必须额外勾选"我已知晓数据将丢失"，否则服务端以 `DANGEROUS_OPERATION_UNCONFIRMED` 拒绝。
- **执行审计**：发布记录持久化环境、操作类型、逐语句耗时、总耗时（`duration_ms`）、变更摘要与完整执行日志；成功与失败（含堆栈）均可回查，发布历史新增"详情"弹窗。
- **Doris 连接器**：新增 `DorisDataSourcePlugin`，复用 MySQL 线协议、默认端口 9030；发布与目录能力与 MySQL 数据源一致。

## New Features

- 数仓分层"发布目标"配置：分层管理弹窗按开发/生产环境分别绑定数据源、目标库与可选 Schema，支持整组替换保存（`GET/PUT /api/workspaces/{workspaceId}/warehouse-layers/{layerId}/targets`）。
- 发布预览接口：`POST .../models/{id}/publication/preview` 返回操作类型、变更列表与最终 DDL，不做任何写入。
- 发布记录详情：历史列表可查看每次发布的 DDL、变更、耗时与执行日志。
- Doris 数据源类型：连接器、展示与发布链路完整支持。

## Improvements

- 发布弹窗全面重构：环境选择 → 目标解析 → 变更对比 → DDL 预览 → 确认勾选 → 执行，替代原先"手选数据库 + 只建表不校验漂移"的流程。
- 模型编辑器按引擎动态渲染物理属性表单；未知引擎保留原值不丢失。
- 发布按钮文案与结果提示对齐实际行为：发布只回读物理表结构，不登记资产目录，并给出"去元数据采集"的引导入口。

## Bug Fixes

- 发布环境与数据源连接状态不再混用同一字典，避免把连接状态渲染为环境标签。
- 修复发布成功文案中"已采集元数据"与实际行为（回读物理表结构）不符的表述。

## Breaking Changes

- 发布请求体由"数据源 + 库 + Schema"改为"environment（+ acknowledgeDataLoss）"，目标由分层绑定解析；旧的逐字段目标参数不再被接受。
- 发布操作在结构有漂移时默认执行 `ALTER TABLE`（原先只做结构校验或不修改）；含删除列的变更必须显式确认数据丢失。
- `yak_ops_modeling_model_publication` 新增非空约束列（环境、操作等），发布记录表结构变化见 `V11__v1_13_0.sql`。

## Compatibility

- v1.3.0 起本仓库只支持全新安装基线 + 前向迁移，本版本延续该契约；`V11__v1_13_0.sql` 为不可变发布迁移，不提供从旧库的升级路径。
- 既有 API 的变更仅限上述发布相关端点；分层、模型其余接口不变。
- 物理表属性以 JSON 存储，仅接受当前引擎注册表声明的键；未知引擎的原有取值原样保留。

## Upgrade Guide

- 全新安装按基线迁移自动完成；`release.env`、`pom.xml`、`yak-ops-ui/package.json` 与 `compose.yaml` 均已对齐 1.13.0，可用 `bash scripts/release/check-release-metadata.sh v1.13.0` 复核。
- 从 v1.12.0 镜像升级：替换镜像标签为 `weifuwan/yak-ops:1.13.0` 与 `weifuwan/yak-ops-api:1.13.0`，启动时 Flyway 自动应用 `V11__v1_13_0.sql`；发布为不可变迁移，请勿手工改写库中 `flyway_schema_history`。
- 使用发布功能前，先在"数仓分层"为每个分层的开发/生产环境绑定目标库；未绑定的分层发布会被拒绝。

## Known Limitations

- Paimon / Hive 暂无数据源连接器（本版本数据源插件仅 JDBC 系），相应引擎的物理属性表单待连接器交付后启用；表单按引擎注册数据驱动，接入即生效。
- 发布当前仅支持 JDBC 系引擎的物理执行；非 JDBC 目标不在本版本范围。
- 发布历史固定返回最近 50 条；更早记录不在列表分页范围。
