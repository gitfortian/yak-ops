## Overview

v1.16.0 落地语义模型的"边"（FYOIP-21）：逻辑模型之间可以声明多对一关系（有序复合键），模型字段获得独立于数据类型的时间角色标记，标准字段 / 模型字段 / 指标获得业务同义词，DWD/DWS/ADS 模型可声明粒度；语义模型可导出为 Apache Ossie `0.2.0.dev0` YAML 投影。关联键引用字段 `en_code` 而非字段行 id——模型字段在每次保存时整批删除重建，行 id 不稳定，编码才是稳定契约。治理新增两条规则（关系键未绑标准、粒度未声明），本期只产生 Issue、不计入健康分。迁移为三张新表加三个列（`grain_note` 可空、`is_time` 默认 0、`scored` 默认 1），存量数据无需回填。

## Highlights

- **关系是一等公民**：`yak_ops_modeling_relation` + `yak_ops_modeling_relation_column` 表达星型模型的多对一连接；`to` 侧必须为维度表，`from` 侧必须非维度表；关联键必须已绑定数据标准，否则拒绝保存。
- **键引用编码而非行 id**：键对存 `from_field_code` / `to_field_code`，读取时按 `(model_id, en_code)` 解析；字段被移除后关系进入"字段已移除"显式状态，重新添加同编码字段即自愈，永不悬空。
- **时间角色独立于类型**：`is_time` 是分析角色标记——整数型 `d_year` 可以是时间维度，日期时间型 `created_at` 可以只是审计戳；迁移默认全部关闭，不静默升级任何存量字段。
- **同义词旁路表**：`yak_ops_modeling_synonym` 按 `(target_type, target_id)` 挂同义词，REST 三种目标类型全量支持，UI 本期仅模型字段。
- **粒度声明**：`grain_note` 由人在基本信息页签填写（"一行 = 一个订单明细行"），只产生治理 Issue、不阻断保存——阻断会让全部存量模型在升级后不可保存。
- **治理只出 Issue、不计分**：两条新规则写入的 Issue 带 `scored=0`，健康分聚合只统计 `scored=1`，升级后不会因存量模型缺粒度而拉低分数。
- **Ossie 只投影不存储**：导出为只读 YAML，规范版本固定 `0.2.0.dev0`；指标仅在恰好绑定一个模型字段时合成基础聚合，其余跳过并写入 `custom_extensions`。

## New Features

- **关系 API**：`/api/v1/data-modeling/models/{modelId}/relations` 提供 `GET`（双侧列表）、`POST`（创建）、`POST .../relations/proposals`（按标准匹配推荐键对，最多 3 组）；`/api/v1/data-modeling/relations/{relationId}` 提供 `PUT` / `DELETE`。
- **粒度 API**：`PUT /api/v1/data-modeling/models/{modelId}/grain`。
- **同义词 API**：`GET|PUT /api/v1/data-modeling/synonyms`（按目标整组替换，事务性）。
- **语义导出 API**：`POST /api/v1/data-modeling/models/{modelId}/semantic-export` 返回 Ossie YAML；含一跳关系，相关数据集至少声明主键、关联键与 `is_time` 字段。
- **前端**：模型详情新增「关系」页签（按健康状态排序的关系卡片 + 新建抽屉，未绑标准以橙色左边框呈现）、字段页签新增时间角色开关与同义词标签编辑、基本信息页签新增粒度声明、新增「语义导出」页签（YAML 预览 + 复制 / 下载，未发布模型展示"设计态名称"横幅）。
- **治理规则**：`MODEL_RELATION_KEY_UNSTANDARDIZED`（HIGH）、`MODELING_GRAIN_UNDECLARED`（MEDIUM），目标类型新增 `MODELING_MODEL`。
- **错误码**：19515–19529（关系名重复、自关联、目标非维度表、维度表作为多端、关联键缺失 / 未绑标准 / 键对重复 / 为空、模型存在关系禁止删除、关系不存在、粒度超长、同义词不合法、同义词目标无效、维度表声明粒度被拒）。

## Improvements

- 模型详情接口（`detail`）附带 `grainNote`、字段 `isTime` 与字段 `synonyms`；保存链路透传两个新属性，同义词走独立端点，不改变既有校验顺序。
- 关系创建接口内置键对提案：按同标准 > 同名同类型 > 同名不同类型排序，未绑标准的候选以 `selectable: false` 返回并说明原因。

## Bug Fixes

- 无（本版本为纯新增功能，未修复既有缺陷）。

## Breaking Changes

- **存在语义关系的模型禁止删除**：`ModelServiceImpl.delete` 在存在关系时返回 `MODEL_HAS_RELATIONS`，需先删除关系。此前模型删除不受限。
- **DIM 模型详情页不再提供「新建关系」入口**：维度表只能作为关系的 `to` 一端。

## Compatibility

- 迁移 `V14__v1_16_0.sql` 为纯新增：三张新表 + `grain_note`（NULL）+ `is_time`（默认 0）+ `scored`（默认 1），不修改既有列与索引；存量模型、任务与历史 Issue 的计分行为不变。
- 关系、同义词、导出端点均为新增，不触碰既有 REST 契约。
- Ossie 投影的兼容承诺仅限文档内固定的规范版本 `0.2.0.dev0`；规范升级可能改变导出内容，且导出不回写任何数据。

## Upgrade Guide

1. 停机执行 Flyway 迁移（或随启动自动迁移）至 `V14__v1_16_0.sql`。
2. 确认 `yak_ops_modeling_model.grain_note` 为 NULL、`yak_ops_modeling_model_field.is_time` 为 0 属预期状态。
3. 升级后首次治理扫描会出现两类新 Issue（粒度未声明、关系键未绑标准）；按提示在模型页补齐即可消除。两类 Issue 本期不计入健康分。
4. 若此前依赖"无条件删除模型"的脚本或流程，需先清理该模型的语义关系。

## Known Limitations

- 关系仅支持多对一，无桥接表与自关联；跨工作空间不可建关系。
- 指标导出仅覆盖可移植聚合白名单（SUM / COUNT / MIN / MAX / AVG）；派生与复合指标、窗口函数、方言函数本期一律跳过并在 `custom_extensions` 声明。
- 维度成员（枚举值暴露）与值级同义词未实现；码表绑定已存在，成员查询面留给后续提案。
- 语义模型不做查询执行，关系仅表达"可连接"，不生成 SQL。
- 语义导出不校验物理表是否真实存在；发布记录过期属于发布模块的数据完整性问题，本期以治理 Issue 形式呈现（后续候选规则）。
