# Yak Ops v1.4.0

**Released:** 2026-10-24

## Overview

v1.4.0 重点完善 MySQL CDC 的 Schema Evolution、Snapshot/Binlog 恢复与 JDBC 目标表结构处理，并改善 Data Sync 及管理页面的可靠性。该版本包含较多运行时重构；升级前必须核对现有任务、Checkpoint 和元数据库的兼容性。

## Highlights

- **实时表结构演进：** MySQL CDC 可将受支持的结构变化独立于行数据进行协调；MySQL / PostgreSQL JDBC 目标支持经过校验的 DDL，运行时拒绝不受支持或结果不确定的变更。
- **安全删除字段：** 管理范围内的非主键 DROP COLUMN 需要显式开启 `allowDropColumns`；默认禁止破坏性 DDL，不自动删除仅存在于目标端的字段。
- **CDC 恢复可靠性：** 修复 GTID / Binlog Offset 比较、空表 Bootstrap、Schema History 与历史 DDL 恢复问题；快照状态采用更紧凑的版本化编码并保留已实现的旧格式读取路径。
- **任务界面与工程化：** Data Sync 列表、编辑器、详情、日志及 Data Source / Schedule / Management / Dashboard 完成职责拆分，改善查询生命周期和交互稳定性。

## New Features

- 新建的 MySQL CDC → MySQL / PostgreSQL 实时任务提供“同步结构变更”配置；其启用行为以任务目标和实际保存参数为准。已存在而未包含该字段的任务不会被静默转换为启用。
- 提供独立 Schema Change Event、Schema Coordinator 与目标 JDBC MetadataApplier；支持经校验的列新增、部分类型变化、受控删除及 DDL 预览。具体支持边界以实际 JDBC Dialect / Schema 检查为准。
- 可显式允许管理范围内的 DROP COLUMN。该操作不可逆，应在启用前备份；非管理列、主键或不满足前置条件的目标会拒绝执行。

## Improvements

- MySQL CDC Snapshot/Binlog 对齐、GTID 与偏移顺序、Schema History 持久化/恢复和 Snapshot Checkpoint 编码更加严格；不将全部历史状态格式视为自动兼容。
- JDBC 目标结构对账和 DDL 有界重试使用真实目标元数据作为判断依据，未确认的执行结果不自动当作成功。
- 前端使用更清晰的 Feature Ownership 和 TanStack Query 生命周期管理，减少跨用户/Workspace 缓存混用及旧轮询逻辑；日志查看器交互与主题表现得到调整。
- CI 按变更范围选择测试，正式 Release Gate 仍执行全量后端测试、前端验证、分发包与 Compose Smoke。

## Bug Fixes

- 修复空 MySQL 表首次启动 CDC 时可能产生不完整 Schema History，导致后续 Binlog Row 无法找到表结构的问题（[#1706](https://github.com/weifuwan/yak-ops/pull/1706)）。
- 修复 Binlog/GTID 偏移比较边界及相关快照水位处理（[#1707](https://github.com/weifuwan/yak-ops/pull/1707)）。
- 修复 CDC 字段变更后的 Schema History / DDL 恢复与 VARCHAR 扩容处理（[#1684](https://github.com/weifuwan/yak-ops/pull/1684)、[#1687](https://github.com/weifuwan/yak-ops/pull/1687)、[#1710](https://github.com/weifuwan/yak-ops/pull/1710)）。
- 修复同步结构变更开关缺少 Field 上下文导致编辑器崩溃的问题（[#1688](https://github.com/weifuwan/yak-ops/pull/1688)）。

## Breaking Changes

- 本版没有新增 Flyway SQL 脚本；v1.3.0 发布的 `V1__baseline.sql` 不应修改，也不允许通过 Flyway `repair` 绕过旧库差异。
- 新建实时任务与旧 Task Definition 的 Schema Evolution 默认行为可能不同：新建任务应核实开关状态，旧定义缺失开关时仍视为关闭。DROP COLUMN 保持默认禁止。
- **不承诺全部 v1.3.0 及更早的持久化 CDC Checkpoint / Offset 状态可无条件恢复。** 尽管本版保留了部分旧格式读取路径，跨版本状态恢复必须使用真实生产版本的状态副本验证；失败时不得跳过校验或直接删除状态来强行恢复。
- 此前 v1.0.0–v1.2.0 的元数据库依旧不支持直接复用 v1.3.0 的新安装基线；v1.4.0 不提供该历史版本的自动迁移。

## Compatibility

- 运行环境：Java 21；Yak Ops 元数据库为 MySQL。实际支持的数据库版本以 Release Gate 和受控环境测试为准。
- 数据同步范围：JDBC Source/Sink 涉及 MySQL、PostgreSQL、Oracle；实时 Source 为 MySQL CDC。**不代表 PostgreSQL CDC 或 Oracle CDC 已实现。**
- 实时目标 DDL 演进适用于受支持的 MySQL / PostgreSQL 路径；Oracle 目标不开放此运行时 DDL 开关。
- 不对未验证的跨版本状态转换、分布式 exactly-once、任意 DDL 兼容性作承诺。

## Upgrade Guide

1. 备份现有 v1.3.0 MySQL 元数据库、任务定义、数据卷与 CDC 持久化状态，记录当前运行中的任务和版本。
2. 在备份副本上检查 `flyway_schema_history` 与 `V1__baseline.sql` 校验和；本次无 V2 迁移脚本。不得改写已发布的 V1，也不得凭校验通过推定所有任务状态可兼容。
3. 针对正在运行的 CDC 任务，记录 Checkpoint / Offset 并在隔离环境使用 v1.4.0 对真实旧状态执行恢复验收；如果失败，保留旧版本和原始状态，制定明确切换方案。
4. 核对实时任务“同步结构变更”和“允许删除字段”开关，特别是新建与历史 Task Definition 的默认差异。先使用测试表验证 DDL，不允许默认开启破坏性操作。
5. 使用明确的 `1.4.0` 分发包或 Docker Tag 在预发布环境完成启动、任务执行与取消/恢复、调度及数据正确性验收，再切换生产流量。
6. 回滚时恢复经过验证的旧版本镜像和备份数据。已执行的破坏性目标 DDL 不能通过镜像回滚自动撤销。

## Known Limitations

- DROP TABLE、RENAME 等不属于已承诺的自动 Schema Evolution 范围；只有显式允许且满足条件的管理字段可以删除。
- Oracle JDBC 目标的实时 DDL 演进限制仍然存在；PostgreSQL / Oracle CDC Source 未在本版实现。
- v1.3.0 → v1.4.0 运行状态和历史任务配置应经过专门验收，不能因全新任务测试通过就视为兼容。
- 发行版正式测试结论需以该版本提交的 Release Gate、Manual E2E 和附件为准；本说明不预先宣称尚未执行的验收已通过。
