# Yak Ops v1.4.0

**Released:** 2026-10-24

本文件记录 1.4.0 版本的既定产品行为。本仓库尚未为该版本创建 Git Tag 或 GitHub Release，发布状态见 [Releases 索引](README.md)；下文 Downloads 与 Compatibility 描述的是当前实际可获取的内容。

## Overview

本版补齐「数据建模」产品的第一段完整链路：数仓规划、数据标准、数仓分层与维度建模。用户可以在同一个工作空间内先定义分层与业务树，再沉淀可复用的字段标准，最后把明细表与维度表建成逻辑模型并逐字段管理，取代此前只能靠文档和口头约定对齐表结构的方式。

## Highlights

- **分层成为可配置对象：** 预置 ODS / DWD / DWS / ADS / DIM 五层，允许新增自定义分层。逻辑模型表名前缀直接取自所选分层的编码，不再硬编码 `dwd_` / `dim_`。
- **规划编码统一命名空间：** 业务分类、数据域、业务过程、数据集市、主题域共用一套全局编码，重名在写入时即被拒绝，避免后续出现多套各自为政的命名。
- **字段标准可继承：** 字段绑定标准后，编码、类型、长度精度由标准提供，模型侧不必重复定义口径；标准自身保留安全等级与业务口径。
- **维度建模形成闭环：** 明细表与维度表支持字段级建模（主键、非空、分区、绑定标准、批量录入、从物理表导入），并从树节点直接进入编辑。
- **数据库变更全部前向：** V2 只新增 13 张表，不修改任何既有表结构，也不读取、不改写既有业务表数据。

## New Features

**数仓规划**（入口 `/data-modeling/warehouse-planning`）

- 业务分类、数据域、业务过程的创建、编辑、删除与树形展示（[FYOIP-7](../yoips/FYOIP-7-data-modeling-warehouse-planning.md)，PR #4）。
- 应用层数据集市与主题域，与维度建模的应用层树共用同一批节点（PR #10）。
- 规划编码在全局唯一，跨节点类型也不可重复；负责人信息在成员关系结束后保留。

**数据标准**（入口 `/data-modeling/data-standards`）

- 标准分类树与字段标准两级结构，分类可嵌套（[FYOIP-8](../yoips/FYOIP-8-data-modeling-data-standards.md)，PR #6）。
- 字段标准包含中文名、英文编码、五种逻辑类型（`STRING` / `BIGINT` / `DECIMAL` / `DATE` / `TIMESTAMP`）、长度或精度、非空要求、安全等级（`PUBLIC` / `INTERNAL` / `SENSITIVE` / `CONFIDENTIAL`）、负责人与业务口径。

**数仓分层**（入口 `/data-modeling/warehouse-planning` 内）

- 预置 ODS 贴源层、DWD 明细层、DWS 汇总层、ADS 应用层、DIM 公共维度层，首次访问时自动初始化（PR #8）。
- 自定义分层编码须匹配 `^[A-Z][A-Z0-9_]{0,31}$`；预置分层不可删除。
- 分层必须先绑定数据源才能启用，维度建模只能选择已启用的分层。

**维度建模**（入口 `/data-modeling/dimension-modeling`，[FYOIP-9](../yoips/FYOIP-9-data-modeling-dimension-modeling.md)）

- 概念维度：公共层维度挂数据域，应用层维度挂数据集市，编码在其归属范围内唯一。
- 逻辑模型：本期支持 DWD 明细表与 DIM 维度表。表名为「分层编码小写 + `_` + 用户填写的后缀」，全名不超过 64 字符；切换分层时重算前缀。
- 字段：支持主键、非空、分区（每个模型至多一个）、绑定数据标准、批量录入，以及从已配置数据源导入物理表结构。
- 批量录入：除「每行一个字段」的分隔符格式外，可直接粘贴 `CREATE TABLE` 文本解析字段定义，解析不出的行降级为手填（PR #16）。
- 模型检索：右侧列表支持按关键词、模型类型、数仓分层、负责人、数据域、数据集市六个维度过滤，走服务端查询与分页（PR #16）。
- 存储属性：`DAILY_INCREMENTAL` 或 `DAILY_FULL`，数据保留天数取值范围 1～36000。
- 树形导航：公共层按「分类 → 数据域 → 维度 / 业务过程」，应用层按「数据集市 → 主题域 → 维度」组织，旧的两个扁平列表路径重定向到树。
- 删除保护：被引用的分类、数据域、业务过程、数据集市、主题域与概念维度拒绝删除并返回 409；逻辑模型删除时其字段随之移除。

## Improvements

- 新增 `yak-ops-business-modeling` 业务模块承载四块建模能力，与数据集成、任务执行模块解耦。
- 建模写路径统一使用 `revision` 乐观锁，错误码经全局处理器映射为对应 HTTP 状态。
- 元数据迁移收敛为单个 `V2__v1_4_0.sql`，与 `V1` 基线并存，延续「每个版本一份前向迁移」的约定。
- 前端新增共享表单与校验模块，字段类型、精度与编码规则在页面与测试中共用同一份定义。

## Bug Fixes

None — 本版为新增能力，没有独立记录的既有缺陷修复。

## Breaking Changes

None — 本版不修改既有 REST 契约、配置项与运行状态格式。数据库变更为纯新增表，不涉及既有表结构与数据。

## Compatibility

- 运行要求 Java 21；Yak Ops 元数据库使用 MySQL 8。
- 升级路径覆盖 v1.3.0（即含 `V1__baseline.sql` 基线的元数据库）。v1.0.0～v1.2.0 的元数据库仍不在支持范围。
- 从物理表导入字段依赖已配置的 JDBC 数据源，覆盖 MySQL / Oracle / PostgreSQL 的 Catalog 查询。
- 未验证的数据库版本、数据规模与部署组合不能作为正式承诺；可运行范围以本仓库 `master` 上 1.4.0 版本元数据对应的提交为准。本版尚未执行 Release Gate，也没有对应的 Git Tag、分发包与镜像。
- 本版未执行浏览器端自动化 E2E 或跨浏览器验收，前端交互的验证边界见 Known Limitations。

## Upgrade Guide

**从 v1.3.0 升级：**

1. 先完整备份元数据库。V2 为前向迁移，仓库不提供回滚脚本。
2. 使用 1.4.0 的分发包或镜像直接启动，Flyway 会按版本顺序应用 `V2__v1_4_0.sql`。
3. V2 只做一件事：新建 13 张建模相关表（含索引、外键与 `CHECK` 约束）。它不 `ALTER` 任何既有表，不读取或改写既有业务表的数据。
4. 不要手工修改 `flyway_schema_history`，也不要用 `flyway repair` 跳过校验。
5. 需要回退到 v1.3.0 时，还原升级前的备份；不能假设旧版本可以直接读取已升级的库。

**全新安装：** 使用空的 MySQL 元数据库启动即可，`V1__baseline.sql` 与 `V2__v1_4_0.sql` 会依次执行。

## Known Limitations

- **物理发布未实现。** 本版只产出逻辑模型，不向引擎建表。分层绑定的数据源目前仅作为发布目标登记，建表、幂等与回滚链路尚未提供。
- **模型类型只有 DWD 与 DIM。** 分层已预置 DWS / ADS，但汇总表与应用表尚未开放，字段的度量与聚合方式（`SUM` / `COUNT` / `AVG` / `MAX` / `MIN`）也未实现。
- **没有指标模块。** 字段不提供「从指标导入」，来源仅限手动录入、批量录入、绑定数据标准与从物理表导入。
- **没有逆向建模。** 无法从已有物理表反向生成逻辑模型。
- **数据标准只覆盖字段标准。** 标准代码、度量单位与命名词典不在本版范围。
- **批量录入的 DDL 解析只覆盖标准字段定义子集。** 支持常见列定义、`NOT NULL`、`PRIMARY KEY`（含 `CONSTRAINT ... PRIMARY KEY`）与 `COMMENT`；`DEFAULT` 表达式被忽略，引擎选项、分区、索引、生成列等表级子句直接跳过，不报错；无法映射到五种逻辑类型的列会保留在字段列表中并标注待补全。
- **跨工作空间访问数据源 Catalog 返回 404。** 为防资源枚举，越权访问统一按「不存在」处理，与部分接口的 403 语义不同。
- **前端缺少自动化交互测试。** 页面逻辑由类型检查、静态检查与纯函数单测覆盖，异步交互未做浏览器实跑。
