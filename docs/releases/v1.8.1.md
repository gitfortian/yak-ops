# Yak Ops v1.8.1

**Released:** 2026-10-26

本文件记录 1.8.1 版本的既定产品行为。本仓库尚未为该版本创建 Git Tag 或 GitHub Release，发布状态见 [Releases 索引](README.md)；下文 Downloads 与 Compatibility 描述的是当前实际可获取的内容。

## Overview

本版是 1.8.0 的缺陷修复版：数据建模模块在第一轮端到端测试中暴露的五个问题全部关闭——保存码表缺英文名被拒、打开「绑定数据标准」弹窗即报错、数据源连不上只给一句「服务器错误」，以及派生指标组合出现「支付支付」、逻辑模型表名出现「dwd_dwd」两处命名叠字。没有新增功能，没有数据库迁移。

## Highlights

- **保存码表不再要求英文名。** 码值编辑器只收集编码、中文名与含义，英文名留空是常态而非非法请求；缺少英文名时用码值编码补齐，保存照常成功（`en_name` 落库为编码值）。
- **「绑定数据标准」弹窗可以正常打开。** 首次加载不再把空关键字当参数发出去，服务端也把空白关键字视为「不过滤」，弹窗直接列出可绑定的字段标准。
- **数据源连接测试失败会给出具体原因。** 账号密码错误、库不存在、网络不可达等由驱动返回的原始说明随响应返回，HTTP 状态从 500 改为 400，调用方可以区分「我的配置错了」与「服务端出问题了」。
- **组合名称与编码不再叠字。** 修饰词与原子指标首尾重叠时只保留一份，「最近7天支付支付金额」变为「最近7天支付金额」，编码同样去掉重复段。
- **表名不会重复分层前缀。** 在逻辑模型的后缀输入框里再打一次 `dwd_` 会被自动剥掉，输入框与预览始终显示 `dwd_trade_order`，而不是 `dwd_dwd_trade_order`。

## New Features

None。本版只修缺陷，不引入任何新能力、新端点或新配置项。

## Improvements

- **派生指标组合按语义合并重叠。** 组合名称在拼接每一段时先比较上一段结尾与本段开头的最长重叠并合并，组合编码则丢弃与上一段完全相同的段。此前的行为是把三段原样相加，同一修饰词被选两次或修饰词已包含原子指标名词时就会出现重复词。服务端的 `DerivedComposition` 与前端的 `composition.ts` 使用同一套规则，弹窗预览、可用性检查与落库结果一致。
- **逻辑模型后缀输入自动剥离本层前缀。** 保存前的表名是「层英文编码 + 后缀」，后缀里再带一次层前缀就会写出 `dwd_dwd_trade_order`。现在创建与编辑弹窗在后缀输入时即剥离当前层的前缀（大小写不敏感的重复出现也一并剥离），服务端在创建、编辑与名称可用性检查三处做同样的归一，绕过界面直接调接口也不会写出双前缀。
- **数据源连接测试的错误信息对用户可见。** 连接失败时服务端把驱动异常的第一手说明截断到 200 字符后作为错误详情返回（错误码 `41006`，HTTP 400），凭据部分仍按既有规则脱敏；界面上的失败提示因此能直接说明是密码错、库不存在还是主机不可达。
- **「新建/编辑标准」弹窗的父级标准改为下拉内搜索。** 此前弹窗同时提供一个带「查找」按钮的关键字输入框和一个普通下拉，用户无法判断结果属于哪个控件；现在父标准下拉在弹窗内边输入边查（250ms 防抖，支持中文名与英文编码），下拉底部显示加载、失败与无匹配，回车不再提交表单，已选中的父标准名称在再次搜索后仍然保留。
- **DECIMAL 精度提示改为说明实际结论。** 两个输入框拆开之后，提示不再重复旧的 `总位数,小数位` 写法，而是在精度对合法时直接显示推导出的整数位数（如「整数位 16 位」），半填状态下也不再给出逗号示例。
- **术语统一为「标准代码」。** 弹窗、「标准代码」页签与逻辑模型字段编辑处的「码表」字样统一改为「标准代码」，与数据标准模块的其余文案一致。

## Bug Fixes

- **码值没有英文名时保存整张码表返回 400。** 校验要求英文名非空，而码值编辑器并不收集该字段，用户按界面给出的三列填写后必然被拒；现在英文名缺失或空白时回退为码值编码（该列 NOT NULL 且在表内唯一，编码本身是安全的替代值）。
- **打开「绑定数据标准」弹窗直接报 400。** 弹窗首次加载没有关键字，请求仍带上了空 `keyword`，服务端把「同时给了分类与关键字」和「两者都没给」都判为非法参数；现在前端空关键字不发该参数，服务端把空白关键字当作无过滤条件，只有分类与关键字同时存在时才拒绝。
- **数据源连接测试失败一律返回 500。** 连接被拒是调用方的配置问题，却与真正的服务端故障共用同一个状态码，界面只能显示通用失败；现在 `CONNECT_FAILED` 映射为 400，并携带驱动返回的具体原因。
- **父标准下拉选中后再次搜索会把已选值显示回「无」。** 结果列表刷新时不再改写触发按钮上的标签，选中项与当前结果页分开记忆。
- **命中父标准搜索框回车会触发整张表单提交。** 搜索框现在吞掉回车，只在点击或选择时产生值。

## Breaking Changes

- 无。本版不新增、不删除、不重命名任何端点或配置项，也没有数据库迁移；`41006` 的状态码从 500 改为 400，客户端若曾按「500 即服务端故障」处理该错误码，需要改为按业务失败处理。

## Compatibility

- 运行要求 Java 21；Yak Ops 元数据库使用 MySQL 8。
- 升级路径覆盖 v1.7.0 与 v1.8.0。本版不含新的 Flyway 迁移，元数据库结构停留在 `V6__v1_8_0.sql`。
- 派生指标的组合去重规则对**新建**与**重新组合**（编辑组成、或被引用的周期/修饰词/原子指标改名）生效；已落库且未再编辑的派生指标保持原有编码与名称，不做批量回填。
- 未验证的数据库版本、数据规模与部署组合不能作为正式承诺；可运行范围以本仓库 `master` 上 1.8.1 版本元数据对应的提交为准。本版尚未执行 Release Gate，也没有对应的 Git Tag、分发包与镜像。

## Upgrade Guide

**从 v1.8.0 升级：**

1. 备份元数据库（可选但建议）。本版不执行任何迁移，备份仅用于回退到旧镜像时的一致性保障。
2. 用 1.8.1 的分发包或镜像替换 1.8.0，Flyway 校验和与版本序列均不变，启动时不会应用新脚本。
3. 升级后无需任何数据修复：历史派生指标保留原编码与名称，只有在编辑后才按新规则重算。
4. 需要回退时直接切回 v1.8.0 镜像即可，库结构与本版一致。

**从 v1.7.0 升级：** 先按 [v1.8.0 升级指南](v1.8.0.md)应用 `V6__v1_8_0.sql`，再替换为 1.8.1 的包或镜像；两步之间不需要额外的数据操作。

**全新安装：** 使用空的 MySQL 元数据库启动即可，`V1__baseline.sql` 到 `V6__v1_8_0.sql` 会依次执行。

## Known Limitations

- **组合去重不回溯历史数据。** 1.8.0 之前保存的派生指标不会被批量改名，需要逐个编辑保存才会应用新规则；改名会影响引用它的复合指标表达式，请在业务低峰期进行。
- **表名前缀剥离只认当前层的英文编码。** 在 `dwd` 层的模型后缀里写 `ods_` 不会被剥离，最终表名是 `dwd_ods_...`；这是有意的，只有重复本层前缀才算口误。
- **数据源连接测试的错误详情来自驱动原文。** 不同数据库与驱动版本的措辞不一致，个别驱动会把主机与端口写进消息；凭据已脱敏，但消息本身不做翻译或改写。
- **父标准下拉每次搜索只取服务端首屏结果**，与其余下拉一致，未提供「加载更多」。
- **前端缺少自动化交互测试。** 本版的界面侧改动由类型检查、静态检查与组合/命名纯模块的单元测试覆盖；弹窗与表名输入的行为依据打包后的应用手动回归。
- **发布流程尚未闭环。** 本版通过本地质量检查与手动回归，但未执行 Release Gate，无 Git Tag、分发包、校验文件与 Docker 镜像。
