# Yak Ops v1.9.0

**Released:** 2026-10-27

本文件记录 1.9.0 版本的既定产品行为。本仓库尚未为该版本创建 Git Tag 或 GitHub Release，发布状态见 [Releases 索引](README.md)；下文 Downloads 与 Compatibility 描述的是当前实际可获取的内容。

## Overview

本版新增**数据地图**，是「数据治理」产品下的第一个模块。它把数据源里真实存在的表变成可检索、可治理的资产：采集记录事实，人在事实之上补描述、负责人与数据域，两条写入路径互不覆盖。按 [FYOIP-15](../yoips/FYOIP-15-data-map-metadata-catalog.md) 划定的边界，本版不做血缘、不在地图内建任务与调度、不估算行数与存储大小。

## Highlights

- **采集把数据源变成资产清单。** 手动触发一轮采集，逐个数据源枚举库、schema 与表；同一数据源任一时刻只允许一轮采集，由数据库唯一索引而非应用层判断保证。单表失败只丢一行进度，不会回滚整轮；只有整轮无失败才把本次没见到的表标记为「已消失」。
- **目录可以按域浏览，也可以直接搜。** 左侧是数仓规划的数据域树（只渲染 DOMAIN 与「未分类」，不复制一份分类），右侧是结果表；关键字同时匹配表名、描述与**字段名**，命中字段时明确回报是哪个字段。筛选条件与页码全部在 URL 里，视图可分享、可刷新恢复。
- **治理不会被子夜采集冲掉。** 采集只写 `table_type`、`remarks`、`status`、`last_seen_time`；人工只写 `description`、`owner_id`、`domain_id`。两条 UPDATE 在 SQL 文本层面互斥，没有「合并更新」也没有版本号列，因此一次采集结束不会把正在编辑的表单结果覆盖掉。
- **字段变更会被记下来。** 记录字段新增、删除、类型变更、可空性变更、主键变更与表注释变更六类事件。类型变更只产出一条等值变更，而不是「删一个字段、加一个字段」；首次采集不产生任何记录，避免把建库噪音当成变更。
- **预览有硬预算，不再是「点一下看运气」。** 单次最多 100 行、5 秒、1 MB 字节预算、单元格 200 字符；二进制与大字段只返回占位符，不读取内容；`PROD` 环境直接拒绝；并发上限 4，超出明确返回「正在执行其他预览」。

## New Features

- **元数据采集**：`POST /api/v1/data-map/crawls` 提交，`GET /api/v1/data-map/crawls` 列表，`GET /api/v1/data-map/crawls/{id}` 详情与逐表失败原因。单次采集最多枚举 2000 张表，超过直接以 `CRAWL_TOO_LARGE` 失败而不是截断；整轮时间预算 30 分钟。进程重启后，遗留的 `RUNNING` 会被清扫为 `FAILED` 并释放采集锁，不需要人工干预。
- **资产目录与搜索**：`GET /api/v1/data-map/tables`，支持数据源、库、schema、数据域、负责人、状态、仅未分类、关键字八类条件与前缀匹配的排序。关键字中的 `%`、`_` 按字面量转义；同一用户每秒最多 5 次搜索，超出返回 `SEARCH_TOO_FREQUENT`；服务端计数封顶 1000，界面显示 `1000+` 而不是一个没读到的总数。
- **资产详情与人工治理**：`GET /api/v1/data-map/tables/{id}` 返回基本信息、字段与标签；`PUT /api/v1/data-map/tables/{id}` 修改描述、负责人、数据域。负责人必须是当前工作区成员，数据域必须是数仓规划中真实存在的 DOMAIN 节点，两者都在写入前校验。
- **变更记录**：`GET /api/v1/data-map/tables/{id}/changes`，返回最近 50 条事件。
- **标签**：工作区级标签库的增删改（`GET/POST /api/v1/data-map/tags`、`PUT/DELETE /api/v1/data-map/tags/{id}`）与资产挂载（`PUT /api/v1/data-map/tables/{id}/tags`），同名标签返回 `DUPLICATE_TAG` 而不是静默复用。
- **收藏与最近访问**：`POST/DELETE /api/v1/data-map/tables/{id}/favorite`、`GET /api/v1/data-map/favorites`、`GET /api/v1/data-map/recent`、`POST /api/v1/data-map/tables/{id}/views`，按人记录；总览的「热门资产」按真实访问次数聚合。
- **受限数据预览**：`GET /api/v1/data-map/tables/{id}/preview`，按需触发；文本按字符流截断，超出体积预算时以 `truncated` 说明是行数截断还是体积截断；每次读取写一行审计日志，含调用人与资产，不含样本值。
- **总览**：`GET /api/v1/data-map/overview`，资产总数、纳管数据源数、近 7 日新增、未分类数与热门榜。
- **前端页面**：`/data-governance/data-map/` 下的总览、资产目录、资产详情、采集任务、我的数据五条路由；数据治理作为独立产品进入产品菜单，侧边栏以可折叠分组承载模块内的二级页面。
- **配置项**：`yak.data-map.crawl.worker-count`（默认 2）、`yak.data-map.crawl.queue-capacity`（默认 64）、`yak.data-map.crawl.budget`（默认 30m）、`yak.data-map.preview.max-concurrent-queries`（默认 4）、`yak.data-map.preview.timeout-seconds`（默认 5）、`yak.data-map.preview.cell-characters`（默认 200）。全部带默认值，不配置也能启动。

## Improvements

- **产品侧边栏支持二级分组。** 有子项的导航项渲染为可折叠分组，子项以缩进与竖向导轨线呈现，进入详情页时父项保持展开与高亮。这一改动同样作用于已有的运维中心与管理中心，但它们的扁平结构未变。
- **删除数据域前可以看到影响面。** 数仓规划的删除弹窗会显示「约有 N 张资产，删除后将变为未分类」。计数调用失败时该行不显示，采集故障不会阻塞规划删除；资产不会被连带删除，而是随 `ON DELETE SET NULL` 变为未分类。
- **数据源能力补齐「全量列举」。** 数据源详情原有的列举接口上限 500 张表，用于交互式选择是合理的，但无法作为采集原语；现在新增独立的 `listAllTables`，两条路径的语义不再互相妥协。
- **预览读取按方言配置流式参数。** MySQL 以 `Integer.MIN_VALUE` 逐行流式读取，PostgreSQL 使用有界 fetch size，避免把整表结果集读进内存；调用侧不再按数据库类型分支。

## Bug Fixes

None。本版未单独修复 1.8.x 已发布版本中的缺陷；上述改进项均为数据地图落地过程中的配套改动。

## Breaking Changes

- 无破坏性变更，但有三处需要知情的增量：
  - **数据库**：新增 Flyway 迁移 `V7__v1_9_0.sql`，只创建 9 张 `yak_ops_data_map_*` 表与它们的外键、唯一键，不修改任何既有表、列或索引。升级后元数据库结构停在 V7。
  - **内部服务契约**：`DataSourceCatalogService` 新增 `listAllTables`，`JdbcDialect` SPI 新增带默认空实现的 `configurePreviewStatement`。第三方 dialect 实现无需改动即可编译运行，仅当它需要自定义预览的流式行为时才重写。
  - **前端路由**：新增 `/data-governance/` 前缀并纳入登录后的深链回跳判定；既有路径不受影响。

## Compatibility

- 运行要求 Java 21；Yak Ops 元数据库使用 MySQL 8。
- 升级路径覆盖 v1.8.0 与 v1.8.1。自 v1.8.1 起元数据库结构为 `V6__v1_8_0.sql`，本版追加 `V7__v1_9_0.sql`。
- 采集通过 JDBC 数据源执行，覆盖仓库既有 JDBC 连接器支持的数据库；非 JDBC 数据源不在本版范围。预览同样只对 JDBC 数据源开放。
- 未验证的数据库版本、数据规模与部署组合不能作为正式承诺；可运行范围以本仓库 `master` 上 1.9.0 版本元数据对应的提交为准。本版尚未执行 Release Gate，也没有对应的 Git Tag、分发包与镜像。

## Upgrade Guide

**从 v1.8.0 / v1.8.1 升级：**

1. 备份元数据库。本版会执行 V7 迁移，备份是回退到旧镜像时的唯一可靠手段。
2. 用 1.9.0 的分发包或镜像替换旧版本，启动时 Flyway 自动应用 `V7__v1_9_0.sql`。该脚本只创建新表，不触碰既有数据，无需停机维护窗口。
3. 升级后数据地图是空目录：先在「采集任务」里对目标数据源提交一轮采集，资产才会出现。采集不改变数据源本身，只读取元数据。
4. 回退到 1.8.x 时，库中会多出 9 张数据地图表与一条 V7 迁移记录。本仓库未验证旧版本启动时对「更高版本迁移记录」的校验行为，因此回退应同时恢复第 1 步的备份，或先删除这 9 张表并清理迁移记录。

**全新安装：** 使用空的 MySQL 元数据库启动即可，`V1__baseline.sql` 到 `V7__v1_9_0.sql` 会依次执行。

## Known Limitations

- **边界即设计。** 不提供血缘、地图内的任务与调度、行数与存储大小估算、字段级描述与负责人、非表资产（Kafka、文件）、多级 catalog（Doris、Paimon）与全文索引；这些写在 FYOIP-15 的 Rejected Alternatives 中，属于后续提案而不是缺陷。
- **改名会被当作新资产。** 表或字段改名后，旧行变为「已消失」，新行作为新资产出现，变更记录因此会显示为一次删除加一次新增。本版不做基于列集合指纹的改名识别。
- **采集规模有硬上限。** 单次采集最多 2000 张表、30 分钟预算，超过即失败而不是部分成功；十万级资产下的目录与总览性能未做验证。
- **预览只覆盖非生产环境。** `PROD` 环境一律拒绝；行数、超时、体积与单元格字符数都是硬预算，不是提示。
- **采集锁按数据源维度。** 同一数据源同一时间只能有一轮采集；不同数据源互不阻塞。多个数据源共用同一个采集线程池（默认 2 个线程），排队超过 64 个会被明确拒绝为 `CRAWL_BUSY`。
- **发布流程尚未闭环。** 本版通过本地质量检查与 CI 检查，但没有 Git Tag、分发包、校验文件与 Docker 镜像。
