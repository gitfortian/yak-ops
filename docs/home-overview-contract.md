# Home Overview Contract

Yak Ops 首页只负责读取各能力域已经拥有的事实，不成为新的业务真相中心。本文件记录首页总览的接口、指标语义和查询预算。

## 接口边界

| 能力域 | 接口 / 数据源 | 权限与隔离 |
| --- | --- | --- |
| 数据集与血缘 | `GET /api/v1/home/assets/overview` | 数据集、血缘分别容错；任一模块失败不会伪造为 `0` |
| 数据质量 | `GET /api/v1/home/quality/overview` | 继续使用 `quality:execution:read` |
| 数据服务 | `GET /api/v1/data-service/overview?range=7d` | 复用 Data Service 自有可观测契约 |
| 仪表盘 | `GET /api/v1/dashboards/overview?limit=4` | 复用 Dashboard 稳定 facade，返回轻量计数和最近资产 |
| 数字大屏 | 浏览器 `localStorage`：`yak-ops:digital-screens:v1` | 当前仍是浏览器本地资产，不冒充服务端共享数据 |

不增加一个绕过领域权限的全量 `/home/overview` 接口。质量等受保护数据必须继续通过原权限边界读取；各区域保持独立失败和渐进展示。

## 数据语义

- 查询成功且没有业务记录：返回并展示真实 `0`。
- 模块未启用、权限不足或查询失败：该区域返回/展示不可用状态，不能降级成 `0`。
- 无法证明的指标不展示，也不使用其他字段代替。
- 首页“今日”使用应用所在时区的左闭右开自然日窗口；滑动时间范围继续遵循各业务接口既有边界语义。
- 列表必须是有上限的最近记录，不允许为了首页加载完整资产集合。

## 查询预算

### 数据集

首页数据集总览使用固定三次查询：

1. 一次聚合查询返回数据集总数和窗口内新增数；
2. 一次 `LIMIT` 查询最近更新数据集；
3. 一次 `LIMIT` 查询最近上线数据集。

不再调用 `DatasetService.list()` 后在 JVM 中统计完整数据集集合。

### 血缘

继续使用 `LineageQueryService.overview(...)` 的数据库计数和受限最近关系，不加载完整血缘图。

### 数据服务

数据服务运行概览使用固定四次查询：

1. API 与调用汇总；
2. 按时间桶聚合趋势；
3. 按 API 聚合热门调用；
4. 受限最近失败记录。

不再将时间窗口内全部调用日志加载到 JVM 后聚合。调用日志增加时间/API、状态/时间复合索引以支撑范围聚合和最近失败查询。

### 仪表盘

轻量总览使用：

1. 一次聚合查询返回仪表盘总数和已发布数；
2. 一次 `LIMIT` 查询最近更新仪表盘。

完整 `/api/v1/dashboards` 列表接口保持兼容，首页不再使用它统计总览。

## 兼容性

- 现有首页接口和响应字段保持兼容。
- Data Service `/overview` 的 HTTP 响应结构保持不变，仅将聚合工作下推到 SQL。
- Dashboard 原列表、详情、版本、发布接口保持不变，新增轻量 `/overview`。
- Digital Screen 当前持久化模型不在本次治理中改变。

## 评审清单

- 是否出现无界 `list()` 后再计数或排序？
- 是否引入 N+1 详情请求？
- 是否把查询异常伪装成 `0`？
- 是否绕过原有权限？
- 是否为范围与排序查询提供合适索引？
- 是否保留旧接口兼容性？
