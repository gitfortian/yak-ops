# 维度建模模块重构设计方案

状态：草案（待评审）
范围：模型列表页、逆向建模、模型编辑、模型发布四个页面/流程的重构
不涉及：数仓规划、数据标准、数据指标三个模块的功能调整（仅描述联动关系）

---

## 1. 业务逻辑梳理（现状）

### 1.1 领域模型

维度建模是把"业务视角的数据组织方式"（逻辑模型）落到"物理存储"（目标库物理表）的设计环节，上游依赖三个已交付模块：

```
数仓规划                数据标准                 数据指标
├─ 业务分类→数据域→业务过程   ├─ 字段标准(类型/长度)      ├─ 原子指标(挂业务过程)
├─ 数据集市→主题           ├─ 标准代码表 / 度量单位      ├─ 派生指标(原子+周期+修饰词)
└─ 分层 ODS/DWD/DWS/ADS/DIM └─ 词根(命名词典)          └─ 复合指标(表达式)
        │ 每层每环境绑定发布目标(DEV/PROD 数据源+库+schema)
        ▼
维度建模：逻辑模型 DWD(明细)/DIM(维度)/DWS(汇总)/ADS(应用)
        │ 字段：逻辑类型/主键/非空/分区/聚合方式 + 绑定标准/代码表/单位/指标
        ▼
发布：按分层绑定定位物理目标 → 生成 DDL(CREATE/ALTER) → JDBC 执行 → 元数据快照
```

关键既有契约（重构必须保留）：

- 模型类型与分层一一绑定（`MODEL_LAYER_CODE`: dwd/dim/dws/ads），命名规则开启时表名由 `分层前缀_词根_过程编码_限定词` 组合。
- 发布目标由分层绑定决定，用户不可输入（`yak_ops_modeling_layer_target`，每层每环境一行）。
- 发布记录 append-only，钉住 `datasource_revision`，含 DDL、diff、执行日志；UNKNOWN 状态走 reconcile 对账。
- 凭据不出数据源边界：建模模块只经 `DataSourceLookupService` 拿连接。
- 乐观锁 `revision` 全模块通行；错误码 19xxx 段精确映射。

### 1.2 四个页面的问题诊断

#### 模型列表页（`dimension-modeling/index.tsx`，881 行）

| 问题 | 证据 |
| --- | --- |
| 一棵树混杂 6 种语义（分类/域/概念维度/业务过程/集市/模型），认知负担重 | `Selection = ROOT\|CATEGORY\|DOMAIN\|DIMENSION\|PROCESS\|DATAMART` 联合类型硬拼 |
| 树由 3 个 API 拼装，子节点纯前端内存过滤，1000 条截断 | `getModelCatalog` 循环拉 10 页，`truncated` 提示"只显示最近 1000 个" |
| 只有根节点+有过滤才走服务端分页，大数据量下必然卡顿 | `model-panel.tsx` 双路径渲染 |
| 发布状态只是 Badge，无"待发布工作流"视角 | 用户看不出哪些模型改了还没发布 |
| 无批量操作 | 批量发布/批量删除缺失 |

#### 逆向建模（`dimension-modeling/reverse/index.tsx`，YOIP-12）

| 问题 | 证据 |
| --- | --- |
| 单表一次性向导，三步挤在一个页面，接几十张表要重复几十次 | 截图可见，单选表无批量 |
| 只映射类型，不自动绑定数据标准/词根，表与列注释利用不充分 | `reverse-modeling-draft.ts` 仅 `mapPhysicalColumn` |
| 存储策略/生命周期写死 | `storagePolicy: "DAILY_INCREMENTAL"`、`lifecycleDays: 30` 硬编码 |
| 无草稿态，必须一次走完；目标层同名冲突到最后一步才报错 | 无 save-draft，保存前才 `checkModelName` |
| 类型只允许 DWD/DIM | `useState<"DWD" \| "DIM">` |

#### 模型编辑器（`logical-models/editor.tsx`，约 1450 行）

| 问题 | 证据 |
| --- | --- |
| 单页巨型表单，14+ 基本信息字段与字段表格混排 | 截图可见 |
| 表名词根组合器交互别扭（`dwd_ [选择词根] _pay [限定词]`），实时反馈弱 | `naming-composer.ts` |
| 字段表格无标准/指标绑定的结构化视图；`metricId` 保存透传但无控件 | 编辑器注释自述"本版本无对应控件" |
| 无变更感知：与已发布版本相比改了哪些字段不可见 | 模型表可变，无版本快照 |
| 无影响分析：谁在引用这个模型/字段 | references API 仅标准/指标侧有 |

#### 发布（`logical-models/publish-dialog.tsx`）

| 问题 | 证据 |
| --- | --- |
| 弹窗式单模型发布，无环境流水线（DEV→PROD promotion）视角 | 一次一个模型 |
| 错误恢复脆弱：目标加载失败即死路 | 截图"分层与发布目标加载失败，请稍后重试" |
| 无批量发布、无发布前检查清单 | 逐模型点发布 |
| 模型改后再发布，历史发布记录无法还原"当时发布的定义" | 发布记录只存 `model_id`，模型无版本快照 |

### 1.3 后端能力缺口（前端重构掩盖不了的部分）

1. **模型无版本化**：`yak_ops_modeling_model` 是可变行 + revision 乐观锁，与项目"task-definition identity & immutable definition versions"的不变量不一致。发布记录（append-only）回指 `model_id`，不回指版本。
2. **发布历史硬上限 50 条**不分页；catalog 表列举上限 200。
3. **逆向建模无服务端草稿概念**：批量逆向时前端要串联 N 次 catalog 调用，无事务/无中间态。

## 2. 重构目标与设计原则

**总目标：从"表单 + 弹窗的 Demo 页面"升级为"以模型生命周期为中心的设计工作台"。**

1. **生命周期可见**：任何时刻用户能回答"这个模型处于什么状态、和物理表差多少、上次发布是什么时候、谁改的"。
2. **批量优先**：逆向接库、发布上线都是批量场景，单模型操作保留但不再是主路径。
3. **变更驱动**：编辑器和发布都围绕"变更集"（与最近发布版本的 diff）组织，而不是裸表单。
4. **保留既有契约**：类型↔分层绑定、分层决定发布目标、命名规则、凭据边界、乐观锁与错误码语义全部不动。
5. **分阶段交付**：阶段一/二纯前端或轻后端，阶段三补版本化契约（需先走 YOIP 流程）。

## 3. 目标信息架构

```
维度建模（一个入口，三种视图）
├── 模型工作台（默认页）
│   ├── 分层视图：ODS / DWD / DIM / DWS / ADS（物理视角，展示每层模型数/待发布数）
│   ├── 业务视图：业务分类→数据域→业务过程 / 数据集市→主题（骨架+挂载计数，点击进列表）
│   └── 发布视图：待发布 / 发布失败 / 发布成功（按环境分组）
├── 逆向建模工作台（从列表页进入）
│   └── 数据源→库→schema 导航 + 表多选 + 映射预览 + 批量生成草稿/模型
├── 模型详情页（取代现在的单页编辑器）
│   ├── 概览：基本信息 + 生命周期状态 + 与物理表差异摘要
│   ├── 字段：增强表格（标准/指标绑定、批量粘贴、变更高亮）
│   ├── 引用：指标/标准/发布记录的影响分析
│   └── 发布：环境状态（DEV/PROD 各自结构比对）+ 发布历史
└── 发布中心（从列表页"发布视图"进入）
    └── 变更集 → 环境选择 → 批量预览( diff+DDL ) → 危险确认 → 执行 → 结果
```

三种视图是同一模型集合的三种组织方式，右侧表格组件复用；视图状态写入 URL，可直达、可刷新、可分享。

**设计要点**：

- 现有左树的"概念维度/业务过程叶子直接挂模型"改为**挂载计数**（如 `交易域 / 商品支付 (5)`），点击进列表（服务端分页），不再前端拼树。概念维度的维护入口回归数仓规划，建模侧只读消费。
- 搜索栏能力保留并扩展：增加"发布状态"过滤和"仅看有变更"。

## 4. 详细设计

### 4.1 模型工作台（列表页重构）

- **三视图切换**（分层/业务/发布）替代单一混合树。
- 表格列保留现有（表名/中文名/类型/分层/存储策略/字段数/发布状态），新增 **变更指示**（相对最近发布版本的字段级差异计数，如 `+2 ~1 -0`），点击展开 diff 摘要。
- 行操作收敛为 详情 / 发布 / 更多（删除）；批量操作栏：批量发布、批量删除。
- 1000 条截断改为服务端分页 + 面包屑计数（ planning 节点 → 点击看该节点下的模型列表）。

### 4.2 逆向建模工作台

布局：**左侧源导航（数据源→库→schema→表清单） + 右侧映射工作台**。

1. **选源**：复用 `useCatalogPicker`；表清单支持多选、关键字过滤、全选当前库。
2. **映射预览**（核心新增）：选中表后右侧面板展示列级映射结果——逻辑类型、标准建议（按 `enCode`/中文名对命名词典与字段标准做相似匹配，置信度标注）、无法映射高亮并给出原因。映射规则条（前缀剥离、注释→中文名、标准自动匹配开关）可调整，调整即时重算预览。
3. **批量生成**：每张表一行摘要（目标层/类型/表名/冲突状态），冲突（目标层同名模型已存在） inline 提示并支持"跳过/覆盖目标后缀"。
4. **输出**：支持 **保存草稿**（见 4.5 草稿态）或 **直接创建**；创建走既有 `POST /models` 契约不变，成功后批量跳转编辑器或留在工作台继续。
5. 类型范围维持 DWD/DIM（与既有契约一致）；DWS/ADS 不作为逆向目标（汇总/应用模型由设计产生，不是逆向产物）。

### 4.3 模型详情页（编辑器重构）

单页表单拆为 **页头 + 四个 Tab**：

- **页头**：表名/中文名/类型 Badge/生命周期状态 Badge/负责人/操作（保存、发布、更多）。
- **概览**：基本信息（只读为主，点击编辑进内联编辑）；**与物理表差异摘要**（调用发布 preview 的 NONE/ALTER 结果做只读展示）；最近发布记录摘要。
- **字段**：增强表格——
  - 标准绑定列、指标绑定列（补上 `metricId` 控件，按业务过程过滤可选派生指标）；
  - 批量粘贴（Excel 直接粘贴进表格）、从物理表导入、DDL 导入（保留）；
  - **变更高亮**：相对最近发布版本的新增/修改/删除行着色。
- **引用**：字段标准/代码表/度量单位/派生指标的反向引用清单（消费已有的 references 端点）；被哪些 ADS 模型的字段引用（后续接 data-map）。
- **发布**：DEV/PROD 两个环境卡（目标库、表是否存在、结构是否一致、上次发布时间与结果）、发布历史入口。

命名：词根组合器保留但改为"智能建议 + 手动确认"——进入编辑时根据表中文名/业务过程自动推荐词根组合，用户可换，完整表名与查重状态实时显示。

### 4.4 发布中心（发布重构）

从弹窗升级为**变更集驱动的批量发布**：

1. **组成变更集**：列表页勾选模型 / 发布视图"全部待发布" / 单个模型详情发起。
2. **环境选择**：DEVELOP → PROD 流水线视图；PROD 发布建议先经 DEVELOP 成功（提示，不强制）。
3. **批量预览**：一次返回所有模型的 preview 汇总（每张目标表 CREATE/ALTER/NONE + diff + DDL）；目标未绑定分层的模型 inline 报错并提供"去数仓分层配置"链接（解决截图中的死路问题）。
4. **危险确认**：汇总所有 DROP/缩类型项，统一一次确认。
5. **执行**：逐模型执行并实时刷新进度；UNKNOWN 走既有 reconcile。
6. **结果**：成功/失败清单 + 失败原因 + 重试入口；成功即冻结模型版本（见 4.5）。

发布前检查清单（发布中心顶部）：分层目标绑定状态、命名规则违规、危险变更数、目标连通性。

### 4.5 模型状态机与版本化（阶段三，后端契约扩展）

**状态机**：

```
草稿(DRAFT) ──首次发布成功──> 已发布(PUBLISHED)
已发布 ──模型保存产生差异──> 有变更(CHANGED) ──发布成功──> 已发布(新版本)
   ▲                            │
   └──── 放弃变更(回滚到最近版本) ◄┘
任何状态：发布失败(PUBLICATION_FAILED) 标记最近一次发布结果（不改模型状态）
```

- `CHANGED` 由"当前定义 vs 最近发布版本快照"的 diff 判定，服务端在保存时计算并冗余 `publish_state` 列，列表页直接过滤。
- **版本化**：新表 `yak_ops_modeling_model_version`——发布成功时冻结模型+字段快照，发布记录回指 `model_version_id`。模型本身仍是可变行（revision 乐观锁不动），但每个成功发布对应一个不可变版本。
- **回滚**：把当前定义覆盖为某历史版本的字段集（生成一次新的保存 revision，不删历史）。
- **草稿态（逆向工作台消费）**：`yak_ops_modeling_model` 增加 `draft` 标记（或独立草稿表），草稿不参与发布/引用检查；逆向工作台可保存多张表的草稿后续继续。草稿升级为正式模型时走同一创建契约。

以上涉及持久化格式与公开契约变更，按仓库治理规则需先提交 YOIP 并通过后再实现。

### 4.6 API 设计调整

阶段一/二（复用现有契约，仅新增只读端点或前端组合）：

| 用途 | 方案 |
| --- | --- |
| 列表状态过滤 | `GET /models` 增加 `publishState` 参数（实现上先以前端组合 preview 结果过渡，或直接加列过滤） |
| 批量预览 | 前端循环 `POST /models/{id}/publications/preview` 并发组合（保留后端单模型语义，不加批量端点） |
| 差异计数 | 消费 preview 的 `changes` 长度做 `+A ~C -D` 摘要 |
| 逆向批量列读取 | 复用 `POST /catalog/columns`，前端并发；标准自动匹配在前端用命名词典+字段标准数据本地完成 |

阶段三（需 YOIP）：

| 新增 | 说明 |
| --- | --- |
| `GET /models/{id}/versions` | 版本列表（id、发布时间、发布人、版本号） |
| `GET /models/{id}/versions/{vid}` | 版本快照 |
| `PUT /models/{id}/rollback` | 回滚到指定版本（body: versionId, revision） |
| `GET /models` 增列 | `publishState`、`latestVersionNo`、变更计数冗余 |
| 发布记录加 `model_version_id` | 冻结与回指 |
| 草稿端点 | `GET/POST/PUT/DELETE /reverse-drafts`（或模型表 draft 标记 + 现有 CRUD） |

## 5. 分阶段实施

| 阶段 | 内容 | 后端依赖 | 治理 |
| --- | --- | --- | --- |
| 一 | 模型工作台三视图 + 模型详情页 Tab 化 + 发布弹窗健壮性（目标加载失败引导、错误恢复） | 无 | 常规 PR |
| 二 | 逆向建模工作台（批量/映射预览/草稿直接创建）+ 发布批量预览（前端组合） | 无或轻量（列表过滤参数） | 常规 PR |
| 三 | 模型版本化（新表+发布冻结+回滚）+ 发布中心 + 草稿持久化 | V12 迁移 + 新端点 | **先提 YOIP** |

每阶段保持旧路径可用或明确切换点，避免半重构状态；阶段三落地后删除旧发布弹窗的残留入口。

## 6. 风险与边界

- **不做的**：自动推断模型类型（维持用户显式选择，YOIP-12 既定）；存储策略/生命周期生成 DDL（维持逻辑属性）；整库元数据采集（FYOIP-15 data-map 范畴）。
- **兼容性**：模型/字段表结构在阶段三前不变；命名规则、分层目标绑定等既有契约不动。
- **性能**：1000 条截断由服务端分页根治；发布视图的状态过滤依赖阶段三冗余列，阶段二先前端组合过渡。
