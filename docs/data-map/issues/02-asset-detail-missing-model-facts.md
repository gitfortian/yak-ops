# 02: 资产详情未继承模型事实，且无回链逻辑模型与血缘入口

**对应需求:** 第 1 轮验收 轮1 B2 的**详情半边**（P1） | 阶段: P1

**What to build:** 一张**由逻辑模型发布出来的**物理表，其资产详情应当带上模型已经定义好的业务事实，并能反查回模型。实测 `dwd_item_sales_detail`（模型 `108868468571299840` 发布产物）采集登记后，资产详情显示：负责人「未指派」、数据域「未分类」、业务描述「暂无」、引擎注释「-」——**模型的中文名/负责人/数据域/描述一个都没继承**；页面上也没有回链逻辑模型，更没有血缘 Tab。

**模块归属:** **datamap（详情展示 + 登记时携带事实）**；跨模块引用建模事实时**只读建模的公开契约**，不复制第二套元数据。

**Blocked by:** [01](01-publish-does-not-register-asset.md) 的登记口径（先有登记，才谈得上带事实）；实体关系落点等 [FYOIP-17](../../../docs/yoips/FYOIP-17-asset-entity-registry.md)。

**Status:** ready-for-agent（展示层可先做，登记携带事实需与 01 同步）

**证据（本仓已复核）**
- [tables/detail/basics-tab.tsx:226](../../../yak-ops-ui/apps/web/app/data-map/tables/detail/basics-tab.tsx) `<Fact label="负责人" value={ownerName ?? "未指派"} />`；`:93` `{ value: NO_DOMAIN, label: "未分类" }`；`:122` 「暂无业务描述，点击右上角「编辑信息」补充。」
- 目录侧同样落空：`shared/asset-table.tsx:106` 数据域为空即显示「未分类」。
- 详情页只有 `basics / columns / preview / changes` 四个 Tab，**无回链模型、无血缘入口**。
- 既有语义提醒：`detail-header.tsx:81` 明确「重命名后的新表会作为新资产出现，描述与负责人需要手工复制」——即当前**没有任何来源继承机制**，全靠手工编辑。

**修法（分两步，第二步受 01/FYOIP 约束）**
1. **可先做**：资产已能识别到同名模型时（同 Workspace、同 `db.table` ↔ 模型发布目标地址），详情页增「来源模型」回链条目 + 一键跳转 `/data-modeling/logical-models/{id}`；只读，不改采集数据；
2. **随 01 落地**：登记时携带模型事实（中文名/描述/负责人/数据域），**只填空缺、不覆盖人工编辑**（编辑信息是资产侧的既有能力，`basics-tab.tsx` 的编辑态）；血缘边按 FYOIP-17 的 entity+关系模型登记，键必须走既有 `PhysicalTableAssetKey` 归一，禁止另立字符串键防裂节点。

**验收清单**
- [ ] 打开 `dwd_item_sales_detail` 资产 → 能看到并点进来源模型 `108868468571299840`
- [ ] 手工编辑过的负责人/描述**不被自动覆盖**（幂等重采集后仍是人工值）
- [ ] 无来源模型的表（如同步落地的贴源表）不出现假的「来源模型」条目
- [ ] 数据域/负责人为空时的显示口径与目录列表一致（同一字典，不出现两套文案）
- [ ] 若实现第 2 步：同一物理表重复登记不新增资产行、不重复挂边
