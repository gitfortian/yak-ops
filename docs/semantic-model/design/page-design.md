## 二、关系页签

**布局**：指标卡 → 分组卡片列表。**无图形**：星型拓扑图与树均已否决——一跳多对一范围内它们与卡片列表信息完全重复，卡片是信息密度最高、维护成本最低的形态；树形态留待雪花模型范围的后续提案。

**指标卡**四项：关系数、键已绑标准（比例）、待修复数、粒度声明文本。粒度不是数字，直接展示声明内容，让人一眼看到"一行代表什么"。（粒度的编辑入口在「基本信息」页签，这里只读展示。）

**分组卡片**：按目标维表分组，一卡一关系。

- **卡片标题**：目标维表名（加粗放大）+ 模型类型副标题（DIM · 客户）
- **左侧边框 3px 即健康状态**：绿（键已绑标准）/ 橙（键未绑标准）/ 红（字段已移除或指向已删除模型），比任何图形记号直观
- **次要信息灰色等宽字体**：Join 类型、关联键映射（`customer_id (事实) = customer_id (维表)`，复合键按 `ordinal` 以 `,` 连接）
- **状态标签**：`已绑标准`（绿）/ `{field} 未绑标准`（橙）/ `字段已移除`（红）/ `指向模型已删除`（红，防御性）
- **操作按钮**：卡片底部一行——`编辑关系`、`删除`；未绑标准时第一个按钮替换为高亮橙色的「去补标准」（页内弹窗，见下）
- **排序**：橙/红卡在前（待修复区），绿卡在后；同组按更新时间倒序
- 超过 10 张卡片时按健康分组折叠，分组标题显示计数

**「去补标准」页内弹窗（不打断流程）**

- 入口：字段页签或关系卡片中点击「未绑标准」标签 / 「去补标准」按钮，页内弹出抽屉，**绝不跳页**
- 内容：搜索现有数据标准（按中文名 / 英文编码），候选列表展示标准名、编码、类型、长度
- **继承预览必须显式**：选中标准后展示"绑定后该字段将继承标准的编码 / 中文名 / 类型 / 长度"——当前 `cust_id` 会被替换为 `customer_id` 这类变化必须让用户在确认前看到
- 确认：更新内存中的字段行（`standardId`），复用模型保存链路单次提交（乐观锁），不新增字段级写接口
- 空态：搜不到标准时给「去数据标准新建」链接（新标签页打开），当前页状态不丢失

**DIM 模型的关系页签只读**：维度只能作为 `to` 侧，页面隐藏「新建关系」按钮，列表照常展示。

**空态**：图区显示"这个模型还没有关系。关系决定它能否和其他模型一起被查询。"并给「新建关系」主按钮。

## 三、新建 / 编辑关系抽屉

四步顺序固定，不提供自由跳步：

1. **选目标模型**：可搜索下拉，只列出同 Workspace 且未与当前模型建立同名关系的模型；按分层分组（DIM 在前，因为星型模型里事实连维表是主路径）。当前模型为 DIM 时不进入本抽屉。
   - **空态必须显式解释工作空间边界**：搜不到时显示"未找到匹配的模型。目标模型仅限当前工作空间——如果模型在其他业务线的工作空间，请先切换工作空间；如果尚未创建，请先到「逻辑模型」新建。" 不加这句，跨业务线的用户会把工作空间隔离当成系统 Bug 提工单。
2. **推荐键**：按标准匹配给出最多 3 组候选，每组显示两侧字段、绑定标准名、类型、匹配度。
   - 匹配优先级：同 `standardId` > 同名且同类型 > 同名不同类型
   - 未绑标准的字段置灰且不可选，右侧说明原因
   - 无候选时显示"两侧没有可匹配的标准字段"并给「去补标准」
3. **确认映射**：有序键对列表，可增删；复合键顺序即 `ordinal`。
4. **Join 类型**：`LEFT` 默认，`INNER` 需显式选择。文案说明差异（维表缺失时是否保留事实行）。

**关系名自动生成**：`{from}_to_{to}`，同对第二条起追加 `-2`、`-3`；用户可改，但不必填。

**不可保存的条件**（前端拦截 + 服务端二次校验）：

- 目标模型与当前模型相同
- 目标模型不是 DIM，或当前模型是 DIM
- 键对为空
- 任一键字段未绑定标准
- 键对重复（同一 `from` 字段出现两次）
- 与同对模型间已有关系的键对集合完全相同
- 关系名为空或与同 Workspace 已有关系重名

**保存后**：关闭抽屉、刷新关系图与该模型的关系列表、若存在未绑标准的键则触发一次治理扫描（异步，不阻塞）。

## 四、字段页签

在现有字段表上增加两列，不改其他列。

**时间角色开关**

- 默认关闭，包括 `Date` / `DateTime` 类型字段
- 悬停提示："标记为业务时间维度后可被时间筛选与趋势分析使用。审计时间戳请保持关闭。"
- 表头提供批量动作「标记所有日期字段」，执行前弹出确认并列出受影响字段，避免一键误改

**同义词标签编辑器**

- 标签形式，回车添加，点 `×` 删除
- 单目标最多 5 个，单个词 ≤ 20 字符，去重（服务端唯一键兜底）
- 本期仅模型字段提供编辑 UI；标准和指标的同义词仅开放 REST，不加编辑界面
- 未绑定标准的字段显示红色「未绑标准」标签，并提供「去绑标准」快捷入口

**不可编辑状态**：模型已发布且当前用户无编辑权限时，两列均为只读展示。

**异步与回滚规则（防呆）**

- 时间角色开关与同义词编辑均为**乐观更新**：先改 UI 再发请求；请求失败立即回滚到点击前状态，并 toast 错误原因
- 批量「标记所有日期字段」必须发**一次批量请求**（单次 PUT 提交全部变更），严禁逐字段发 N 个请求——大模型 100+ 字段时逐个请求既慢又可能部分成功
- 批量执行期间按钮进入 Loading 态并禁用重复点击，受影响行显示 pending 视觉态
- 服务端失败：全部回滚，toast 区分「无权限」与「版本冲突」（后者提示刷新页面后重试）；部分成功不存在——批量接口是事务性的

## 五、语义导出页签

- 顶部固定横幅：规范版本 `0.2.0.dev0` 草案提示，说明只做投影、不写回、不作存储格式
- YAML 预览只读、可复制、可下载，文件名 `{model.name}.ossie.yaml`
- 页脚说明本次导出覆盖的模型数量与关系跳数

**发布体检（导出前置确认）**

- 点击「导出文件」后**先弹体检确认框，再下载**，让问题在导出前可见：
  - ❌ 高风险项：N 个关联键未绑标准（导出可成功，但语义完整性存疑）
  - ⚠️ 跳过项：N 个指标未导出（缺唯一字段绑定）+ 字段已移除的关系
  - ✅ 就绪项：M 个关系键已绑标准
- 体检数据与 YAML 来自**同一次导出请求**（接口返回 `{checks, yaml}` 信封），不重复计算
- 用户在体检框点「仍要导出」才触发下载；点「取消」留在页签并可直接跳到问题项
- 「字段已移除」的关系键存在时，体检升级为阻断确认（需勾选"我知道键字段缺失"才能导出）

**两种需要显式提示的情况**：

- 模型尚未发布：`source` 使用分层前缀的表名而非物理表名，横幅追加"该模型未发布，导出的是设计态名称"
- 存在未绑标准的关系键：导出仍允许，但在 YAML 前的提示区列出受影响关系，避免把问题带出去

**指标导出策略**：仅当某指标恰好被一个模型字段绑定时才导出（合成 `AGG(字段)`）；派生 / 复合指标本期跳过，跳过清单展示在提示区并写入 `custom_extensions`。横幅补一句："N 个指标因缺少唯一字段绑定未导出"。合成表达式仅限可移植聚合白名单（SUM / COUNT / COUNT DISTINCT / MIN / MAX / AVG），窗口函数与方言函数一律跳过并声明——目标库是 Doris 还是 Paimon 不影响导出内容。

**跳过原因必须区分两类，文案不同、修法不同**：

| 原因 | 提示文案 | 用户修法 |
| --- | --- | --- |
| 零绑定 | "该指标尚未绑定任何模型字段" | 去模型字段页把字段绑定到该指标 |
| 多重绑定 | "该指标关联了 N 个模型字段，无法唯一确定数据来源" | 展开绑定清单，去指标页解绑多余绑定或确认权威来源 |

提示区每条跳过项可点击展开绑定详情（字段名 + 所在模型），不许只给一个数量。"商品销售额同时绑定了明细表和汇总表"这种二义性，必须让用户看见是哪两个字段，否则他会以为导出功能坏了。

## 六、治理问题列表复用

新增 `MODELING_MODEL` 目标类型，列表与详情只需：

- 目标名称取 `yak_ops_modeling_model.cn_name`
- 点击跳转 `/data-modeling/logical-models/{id}?tab=relations`（粒度问题跳 `?tab=fields`）
- 两类新问题的修复动作分别为「去补标准」和「填写粒度」

不新增治理详情页。

## 七、状态与异常

| 状态 | 表现 |
| --- | --- |
| 无关系 | 图区占位 + 引导文案 + 新建按钮 |
| 关系指向已删除模型 | 红色标记，禁止编辑，仅可删除关系 |
| 推荐接口超时 | 抽屉内局部重试，不影响手写键对 |
| 导出失败 | 抽屉/页签内错误条，保留已生成的 YAML 片段 |
| 权限不足 | 全页只读，隐藏新建/编辑/导出按钮 |

## 八、埋点

用于验证这次改造是否真的被用起来：

- 关系创建成功数 / 尝试数
- 推荐键采纳率（选中推荐候选的比例）
- 「未绑标准」导致的阻断次数（衡量标准覆盖率缺口）
- 语义导出次数，以及导出后是否被复制
- 时间角色开关使用率（区分批量动作与单个切换）
