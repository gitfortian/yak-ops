# Yak Ops v1.1.0 Release Contract

Status: Development

Target Version: `1.1.0`

Current Development Version: `1.1.0-SNAPSHOT`

Target Tag: `v1.1.0`

Depends On:

- [Yak Ops Version Management](./README.md)
- [Yak Ops Architecture](../../ARCHITECTURE.md)
- [v1.0.0 Release Contract](./v1.0.0.md)
- [Data Sync Capability](../capabilities/data-sync/README.md)

## 1. Goal

v1.0.0 已经证明 Yak Ops 可以完成可部署、可验收的数据同步核心链路。

v1.1.0 不以横向增加 Connector 数量为主目标，而是解决：

> 已发布的数据同步任务能否稳定地自动运行，并在常见失败或进程重启后以明确规则继续工作。

版本主题：

```text
Automation & Recovery
```

## 2. Core Scope

v1.1.0 聚焦四条能力：

```text
Offline Scheduling
Execution Retry / Attempt
Offline Concurrency Policy
Realtime Desired State / Auto Recovery
```

Operations Center 同步补齐自动运行与恢复所需的运行态信息。

## 3. Offline Scheduling

Offline Task 在现有手工运行之外增加定时运行能力。

PR1 已建立 [Data Sync Scheduler Contract](../capabilities/data-sync/scheduler.md) 与 Quartz Boundary：

- Business 只依赖框架无关 `ScheduleEngine`。
- Quartz 依赖只进入 Boot。
- JobData 只保存稳定 ID。
- Cron 使用显式 Time Zone。
- misfire 固定为 `DO_NOTHING`。
- PR1 不新增 Schedule 表、不创建 Instance、不实现并发策略和 Retry。

后续 PR 再接入 Schedule Persistence、Trigger Business 与 Operations UI。

第一阶段至少支持：

- Cron Schedule。
- 显式 Time Zone。
- Schedule Enable / Disable。
- 下次触发时间。
- Trigger Source 区分 MANUAL / SCHEDULE。
- 只有 PUBLISHED Task 可以被调度执行。

Scheduler 只负责产生执行请求，不复制 Data Sync Runtime。

## 4. Retry / Attempt

任务失败后允许按显式 Retry Policy 创建新的 Attempt。

至少定义：

- 最大 Attempt 次数。
- Retry Backoff。
- Execution 与 Attempt 的身份边界。
- 最终状态计算规则。
- 手工 Stop 不自动转换成 Retry。

Retry 不能通过复用同一 RUNNING Instance 隐式重跑来实现。

## 5. Offline Concurrency Policy

同一个 Offline Task 被重复触发时必须存在明确并发语义。

v1.1.0 第一阶段只承诺：

```text
SKIP_IF_RUNNING
```

不在本版本承诺 QUEUE / PARALLEL。

## 6. Realtime Desired State / Auto Recovery

Realtime Task 增加期望运行状态，用于区分：

```text
用户希望停止
vs
进程异常导致停止
```

目标行为：

```text
desiredState = RUNNING
        ↓
应用重启 / 旧 active Instance → LOST
        ↓
创建新的 Instance
        ↓
复用同 Task + definitionVersion 的 CDC state
        ↓
从已完成 offset 继续
```

该能力继续保持：

```text
at-least-once
```

不因为自动恢复而声明 exactly-once，也不复活旧 Instance。

## 7. Operations Center

Operations Center 至少补充：

- Trigger Source。
- Last Run。
- Next Run。
- Attempt。
- Retry 状态。
- 失败原因。
- 自动恢复状态。
- 运行耗时。

Data Integration 继续负责 Definition / Publish；Operations Center 负责运行和运行态观察。

## 8. Database Migration

v1.0.0 已发布，因此：

```text
V1__baseline.sql = immutable
```

v1.1.0 所有数据库结构变化必须新增 Flyway Migration，例如：

```text
V2__data_sync_automation.sql
V3__*.sql
```

禁止修改 `V1__baseline.sql`。

## 9. Compatibility

v1.1.0 必须保持：

- Product Version 与 Task `definitionVersion` 相互独立。
- 已有 v1.0.0 Task Definition 可以继续读取。
- 已有 Realtime persisted offset / schema history 不因产品版本升级自动失效。
- Workspace ownership 与 Datasource secret boundary 不变。
- 现有手工运行能力继续可用。

## 10. Explicit Non-Goals

以下能力不属于 v1.1.0：

- Auto Create Table。
- Logical Data Modeling。
- Multi-table Task。
- Transform。
- PostgreSQL CDC。
- Paimon / Hive / File Connector expansion。
- Distributed Runtime。
- Multi-node Worker。
- HA / Leader Election。
- Exactly-once transaction coordination。
- DAG Workflow。
- QUEUE / PARALLEL Offline concurrency。
- Enterprise RBAC。

## 11. Required Acceptance

v1.1.0 除继续执行现有 Quality Gate、JDBC Acceptance、MySQL CDC Cross-Database Acceptance 外，还必须覆盖：

- Cron 到点触发一次 Offline Execution。
- Disable Schedule 后不再触发。
- RUNNING Task 命中 SKIP_IF_RUNNING 后不创建并发执行。
- Retry Policy 按最大 Attempt / Backoff 生效。
- Stop / Cancel 不被误判成可自动 Retry。
- Realtime desiredState=RUNNING 在应用重启后创建新 Instance。
- Realtime 自动恢复继续复用同 definitionVersion 的 persisted CDC state。
- Realtime 自动恢复不会静默退化为 fresh snapshot。

## 12. Release Rule

v1.1.0 继续遵守 [Yak Ops Version Management](./README.md)。

进入正式 Release 前：

```text
1.1.0-SNAPSHOT
      ↓
Scope Freeze
      ↓
1.1.0-rc.N
      ↓
Release Gate
      ↓
v1.1.0
```

任何新增能力必须先进入本 Contract，再进入实现和 Release Gate。
