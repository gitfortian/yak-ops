# Yak Ops v1.3.0 Development Boundary

Status: Development — Task Definition Foundation Reset

This development contract supersedes the withdrawn Multi-Table / Incremental / Long-Running
business roadmap. YakFlow execution capabilities remain independent and do not imply a
functional Data Sync product runtime.

## Scope

- One stable Task Definition identity and append-only executable version history.
- `DATA_SYNC` is the initial Task Plugin, with parameter parsing and Workspace-scoped
  datasource metadata / Schema validation only.
- Task Definition CRUD, publication, immutable version queries and logical deletion.
- Future Workflow nodes reference `definitionId + version`, with an independent node identity.
- No Workflow schema or runtime is created in this release milestone.

## Non-goals

TaskInstance, Attempt, Schedule, Quartz, Metrics, Logs, Worker/Master, distributed execution
and Data Sync ↔ YakFlow integration are not implemented. Existing frontend components remain
unchanged but execution, schedule and operations endpoints are unavailable.

## Migration

Published V1–V3 are immutable. Withdrawn draft V4–V8 are replaced with
`V4__task_definition_foundation.sql`, which removes the old Data Sync product tables
and creates the two new Task Definition tables. Prior draft development environments must
be backed up and rebuilt from V1–V3. Never use Flyway repair to conceal mismatched
development migration history.

## Release readiness

This is a draft scope reset, not a release readiness declaration. Do not publish v1.3.0
without independent migration and Task Definition CRUD acceptance evidence.
