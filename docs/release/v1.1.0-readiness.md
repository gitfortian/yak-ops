## 6. Known Limitations

These are accepted v1.1 boundaries, not hidden future promises:

- Runtime remains single-node.
- No distributed Worker / HA / leader election / fencing.
- No exactly-once transaction coordination.
- Offline concurrency supports only `SKIP_IF_RUNNING`.
- Quartz currently uses RAMJobStore; enabled schedules are reconstructed from Yak Ops DB at startup.
- Schedule Definition currently has no dedicated UI; the backend API is the product contract.
- Retry Policy has no dedicated configuration UI.
- Retry backoff is process-local; a restart during `RETRY_WAITING` does not resume the same Attempt chain.
- Realtime Auto Recovery is startup reconciliation, not a continuous watchdog.
- Realtime continuation remains at-least-once.
- Auto Create Table, Logical Modeling, Multi-table, Transform and additional CDC sources remain out of scope.
