# Yak Ops v1.2.0 Release Notes

Status: Ready — Awaiting Release Candidate

Theme: `Schema-Aware Sync + Smart Runtime`

Yak Ops v1.2.0 重点解决两个问题：

> 系统能否自己理解 Source / Target Schema，并把普通用户不应该维护的 Runtime / Retry 参数内化为系统策略？

本版本在 v1.1.0 的调度、Execution / Attempt、Realtime Desired State、Auto Recovery 与运行诊断基础上，进一步收口 Schema、字段映射、自动建表、运行规划与智能重试。

## Highlights

### Schema-Aware Sync

Data Sync 现在把真实数据库物理结构归一为产品级 Logical Schema：

```text
Datasource Catalog
        ↓
LogicalTable
        ↓
YakTableSchema
        ↓
Target Table Plan
        ↓
Schema Compatibility
        ↓
Controlled Auto Create
```

主要能力：

- Source Metadata Introspection。
- Logical Type Normalization。
- Composite Primary Key 顺序保留。
- MySQL / PostgreSQL / Oracle Target Native Type Planning。
- Target Schema Compatibility。
- 缺失 Target 的显式 Auto Create。
- CREATE TABLE + Table / Column Comment DDL。
- Runtime 执行前重新读取真实 Catalog 并再次校验。
- Task Editor 提供 Schema Preview，DDL 通过目标表辅助入口按需查看。

Auto Create 只处理缺失目标表，不对已存在表执行 ALTER / DROP / DDL Sync。

### Column Mapping

Task 现在拥有稳定、可冻结的字段映射：

```text
Source Field
→ Target Field
```

支持：

- 字段子集。
- 字段重排。
- 字段改名。
- Mapping Editor 手工连接。
- Auto Create 时使用映射后的目标字段名建表。
- REALTIME Source PK 改名后继续完成 Snapshot / INSERT / UPDATE / DELETE。
- Mapping 冻结进 Execution definitionSnapshot。

不包含：

- Expression。
- CAST。
- Custom SQL。
- Transform。

### Smart Runtime

普通用户不再直接维护：

```text
fetchSize
readBatchSize
writeBatchSize
splitSize
sourceParallelism
checkpoint / queue / timeout tuning
```

OFFLINE 新任务默认使用 backend-owned `AUTO` Runtime Policy。

根 Execution 创建时，系统根据：

- Mapping 后 Source Logical Schema。
- 受控 Source Statistics。
- Target 数据库类型。

规划 Effective Runtime Config，并冻结到 Execution Snapshot。

同一个 Execution 的 Retry Attempt 继续复用该冻结配置，不在每次 Retry 时重新规划。

历史没有 policy 的 Runtime Config 继续按 `FIXED` 兼容，避免升级后覆盖已有调优值。

### SMART Retry

新建普通 Task 省略 Retry Policy 时，后端物化：

```text
mode = SMART
maxAttempts = 3
base backoff = 15s
```

SMART 只对明确瞬时失败自动 Retry，例如连接、recoverable / transient、timeout、SQLState 08 / 40 与部分网络错误。

以下错误不会因为“最多 3 次”而无条件重试：

- SQL / Schema 错误。
- 权限错误。
- 完整性约束。
- 产品校验失败。
- 非法参数。
- 能力不支持。
- 未知异常。

写入安全优先：

- OFFLINE APPEND / OVERWRITE 在 Runtime 已启动后不自动重放。
- OFFLINE UPSERT / REALTIME CHANGELOG 可对明确瞬时失败继续 SMART Retry。
- 本版本仍不声明 exactly-once。

### Durable Retry Recovery

`RETRY_WAITING` 的 `nextRetryTime` 已持久化。

Yak Ops 在等待 Retry 时重启：

```text
RETRY_WAITING
        ↓
restart Yak Ops
        ↓
same Execution Root
same taskVersion
same definitionSnapshot
same retryPolicy
        ↓
wait persisted nextRetryTime
        ↓
next Attempt
```

它不会因为进程退出直接把该 Execution 改成 LOST，也不会重新创建新的 MANUAL / AUTO_RECOVERY Root。

### Realtime Task Lifecycle

Realtime Task List 已补齐：

```text
启动
停止
重新启动
```

状态语义：

- PUBLISHED + STOPPED + 无 Active Execution → 启动。
- PENDING / RUNNING / RETRY_WAITING → 停止。
- `desiredState=RUNNING` + 无 Active Execution → 重新启动。
- UNPUBLISHED → 启动禁用。

用户主动 Stop 会把 desiredState 改为 STOPPED，因此后续按钮回到“启动”；它与 desired-state drift 下的“重新启动”不是同一个状态。

## Database Upgrade

v1.2.0 使用一个 forward-only Release Migration：

```text
V3__v1_2_0.sql
```

它按开发期原 SQL 顺序包含：

```text
Data Sync Auto Create Table
→ Data Sync Column Mapping
```

新增：

- `yak_ops_data_sync_task.auto_create_table`
- `yak_ops_data_sync_task.mapping_config`

原开发期 V3 / V4 Draft Migration 已在 Release Freeze 前 squash，不属于最终用户 Flyway 历史。

v1.0.0 / v1.1.0 的 V1 / V2 Migration 保持不可变。

## Compatibility

v1.2.0 保持：

- Product Version 与 Task `definitionVersion` 独立。
- 旧 Task `autoCreateTable=false` 默认行为。
- `mapping_config = NULL` 的隐式同名 Mapping。
- 历史 Runtime Config 无 policy 时按 FIXED。
- 历史 Retry Policy 无 mode 时按 FIXED。
- REALTIME CDC state 继续按 Workspace / Task / definitionVersion 隔离。
- Realtime continuation 继续是 at-least-once。

## Known Limitations

v1.2.0 明确不包含：

- Logical Table Persistence。
- Catalog Refresh / Schema Diff。
- DDL Sync / Automatic Schema Evolution。
- Multi-table Task。
- Transform / Expression / Custom SQL Mapping。
- PostgreSQL CDC 或更多 CDC Source。
- 用户可配置 Runtime Tuning UI。
- 用户可配置 Retry Policy UI。
- Continuous Realtime Reconciliation / 常驻 Watchdog。
- Runtime Trace Retention / Object Storage / Full-text Search / REALTIME Trace。
- 通用 YakFlow Checkpoint 跨进程恢复。
- Distributed Runtime / Worker / HA / leader election / fencing。
- Exactly-once transaction coordination。

## Release Acceptance

v1.2 Required Manual E2E 已冻结为：

- MAPPING-001 — Offline MySQL → PostgreSQL Mapping + Auto Create + Comment + AUTO Runtime。
- MAPPING-002 — Realtime MySQL CDC → PostgreSQL PK Rename + Auto Create + Start / Stop / Resume。
- RECOVERY-001 — Durable Retry Recovery。

三个 Required Manual E2E 已于 2026-10-07 完成人工执行并确认 PASS：MAPPING-001、MAPPING-002、RECOVERY-001。

正式发布身份与最终验收结果以 [v1.2.0 Release Readiness](./v1.2.0-readiness.md) 为准。
