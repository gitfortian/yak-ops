# Yak Ops v1.2.0 Release Contract

Status: Development — Scope Open

Target Version: `1.2.0`

Current Development Version: `1.2.0-SNAPSHOT`

Target Tag: `v1.2.0`

Depends On:

- [Yak Ops Version Management](./README.md)
- [Yak Ops Architecture](../../ARCHITECTURE.md)
- [v1.1.0 Release Contract](./v1.1.0.md)
- [v1.1.0 Release Evidence](./v1.1.0-release-evidence.md)

## 1. Transition Goal

v1.1.0 已完成正式发布，主干开发线进入：

```text
1.2.0-SNAPSHOT
```

本 Contract 只建立 v1.2.0 的版本边界与规划入口，不在 Post-release Transition 阶段提前承诺具体产品能力。

当前状态：

```text
v1.1.0 = RELEASED
v1.2.0 = DEVELOPMENT
Scope = OPEN
Committed Feature #1 = Schema / Logical Table Contract
Committed Feature #2 = Source Metadata Introspection + Logical Type Normalization
Committed Feature #3 = Target Table Planner + MySQL / PostgreSQL / Oracle Dialect
```

任何希望进入 v1.2.0 的新能力，必须先经过独立规划 / Contract 更新，再进入实现；不能因为代码已经开始开发就自动成为 v1.2.0 Release Scope。

## 2. Version Boundary

Product Version 与 Data Sync Task `definitionVersion` 继续保持独立。

```text
Product Version
1.2.0-SNAPSHOT
→ Yak Ops 产品开发线

Task definitionVersion
v1 / v2 / v3 / ...
→ 单个 Data Sync Task 的可执行定义
```

升级 Product Version 不得自动修改 Task definitionVersion，也不得仅因产品版本变化创建新的 REALTIME CDC state identity。

## 3. Published Migration Freeze

v1.2.0 开发开始时，正式 Flyway 历史为：

```text
V1__baseline.sql
V2__v1_1_0.sql
```

两者都已经发布并永久冻结：

- `V1__baseline.sql` 属于 v1.0.0。
- `V2__v1_1_0.sql` 属于 v1.1.0。
- 禁止修改、rename、删除、重排或重新 squash 已发布 Migration。

v1.2.0 开发期间如果需要数据库变化，可以按 [Flyway Rules](../../yak-ops-dao/FLYWAY_RULES.md) 创建高于 V2 的 Draft Migration。

Release Freeze 时：

- 如果 v1.2.0 没有 Schema 变化，不创建空 Migration。
- 如果 v1.2.0 有 Schema 变化，并且 Draft 尚未进入不可重建共享历史，则将同版本 Draft 收口为最多一个正式 Release Migration。
- 在当前发布链下，v1.2.0 的下一个正式 DB Migration 预期为 `V3__v1_2_0.sql`；如果发布链在冻结前发生变化，应以当时已发布的最大 Flyway Version 为准。

## 4. Scope State

v1.2.0 仍保持 Scope Open，但已经开始接受经过 Contract Review 的能力。

当前已承诺：

```text
Schema / Logical Table Contract = COMMITTED
Source Metadata Introspection = IMPLEMENTED
Logical Type Normalization = IMPLEMENTED
Composite Primary Key Order = IMPLEMENTED
Logical Table Persistence = NOT IMPLEMENTED
Catalog Refresh / Diff = NOT IMPLEMENTED
Target Table Planner = IMPLEMENTED
Cross-DB Target Native Type Mapping = IMPLEMENTED
CREATE TABLE DDL Planning = IMPLEMENTED
Auto Create Table Runtime = NOT IMPLEMENTED
```

版本级 Release 资产仍未建立：

```text
Required Manual E2E = NOT DEFINED
Release Notes = NOT CREATED
Release Readiness = NOT CREATED
Release Gate = NOT APPLICABLE YET
```

Schema / Logical Table 权威正文：

- [Data Sync Schema / Logical Table Contract](../capabilities/data-sync/schema-logical-table.md)

进入 Scope Freeze 前，至少需要完成：

- 明确 v1.2.0 的产品主题和 Core Scope。
- 明确 Non-Goals。
- 明确数据库 / Runtime / Connector / UI 的版本边界。
- 明确新增能力对应的自动 Acceptance。
- 明确最终 Required Manual E2E。
- Review 是否存在需要合并的 Draft Migration。

## 5. Development Rules

v1.2.0 开发阶段：

- 新能力必须更新对应 capability contract，而不是只改实现。
- Release Scope 未冻结前，不提前创建正式 Tag / Release。
- `1.2.0-SNAPSHOT` 只表示开发线，不表示 Release Candidate。
- 日常 PR 可以使用条件 CI；正式 Release 仍必须执行 Full Backend Acceptance。
- Release Freeze 前允许对当前版本未发布的 Draft Migration 做安全 squash。
- 已发布 v1.0.0 / v1.1.0 Release Evidence 与 Migration 不得因 v1.2 开发回改。

## 6. Current Explicit Non-Goals

当前已进入 Development，但以下能力尚未进入已承诺实现范围：

- Logical Table Persistence。
- Catalog Refresh / Schema Diff。
- Auto Create Table Runtime。
- Schema Preview UI。
- DDL Sync / Automatic Schema Evolution。
- Multi-table Task。
- Transform。
- PostgreSQL CDC。
- Distributed Runtime / Worker / HA / fencing。
- Exactly-once transaction coordination。

已发布的 `V1__baseline.sql` / `V2__v1_1_0.sql` 继续永久冻结；v1.2 开发不回改 v1.1.0 Final Evidence。

## 7. Next Step

PR1 已完成 Schema / Logical Table Contract。

PR2 已完成 Source Metadata Introspection + Logical Type Normalization。

PR3 已完成：

```text
LogicalTable
      ↓
TargetTablePlanner
      ↓
MySQL / PostgreSQL / Oracle Dialect
      ↓
TargetTablePlan + CREATE TABLE SQL
```

并通过真实 JDBC Acceptance 在 MySQL / PostgreSQL / Oracle 上执行生成的 DDL。

下一步优先推进：

```text
Auto Create Table Runtime
        +
Schema Compatibility Check
```

PR4 才允许在明确的“目标表不存在 + Plan supported”条件下执行 CREATE TABLE；目标表已存在时继续走 Schema Compatibility，不允许覆盖、DROP 或 ALTER 已存在表。

PR4 仍不做：

- DDL Sync / Automatic Schema Evolution。
- DROP / ALTER target。
- Multi-table。
- Logical Table persistence / modeling UI。

v1.2.0 继续保持：

```text
Status: Development — Scope Open
```

只有当主题、Core Scope、Non-Goals、自动 Acceptance 与 Required Manual E2E 明确后，才进入 Scope Freeze。
