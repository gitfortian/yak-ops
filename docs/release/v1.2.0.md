## 1. Transition Goal

v1.1.0 已完成正式发布，主干开发线进入：

```text
1.2.0-SNAPSHOT
```

本 Contract 只建立 v1.2.0 的版本边界与规划入口，不在 Post-release Transition 阶段提前承诺具体产品能力。

当前状态：

```text
v1.1.0 = RELEASED
v1.2.0 = DEVELOPMENT
Scope = OPEN
Committed Feature #1 = Schema / Logical Table Contract
Committed Feature #2 = Source Metadata Introspection + Logical Type Normalization
Committed Feature #3 = Target Table Planner + MySQL / PostgreSQL / Oracle Dialect
Committed Feature #4 = Auto Create Table Runtime + Schema Compatibility Check
Committed Feature #5 = Auto Create Table + Schema Preview UI
Committed Feature #6 = Retry Policy UI + Durable Retry Recovery
Committed Feature #7 = Data Sync Column Mapping Contract + Persistence
```

任何希望进入 v1.2.0 的新能力，必须先经过独立规划 / Contract 更新，再进入实现；不能因为代码已经开始开发就自动成为 v1.2.0 Release Scope。

## 2. Version Boundary

Product Version 与 Data Sync Task `definitionVersion` 继续保持独立。

```text
Product Version
1.2.0-SNAPSHOT
→ Yak Ops 产品开发线

Task definitionVersion
v1 / v2 / v3 / ...
→ 单个 Data Sync Task 的可执行定义
```

升级 Product Version 不得自动修改 Task definitionVersion，也不得仅因产品版本变化创建新的 REALTIME CDC state identity。

## 3. Published Migration Freeze

v1.2.0 开发开始时，正式 Flyway 历史为：

```text
V1__baseline.sql
V2__v1_1_0.sql
```

两者都已经发布并永久冻结：

- `V1__baseline.sql` 属于 v1.0.0。
- `V2__v1_1_0.sql` 属于 v1.1.0。
- 禁止修改、rename、删除、重排或重新 squash 已发布 Migration。

v1.2.0 开发期间如果需要数据库变化，可以按 [Flyway Rules](../../yak-ops-dao/FLYWAY_RULES.md) 创建高于 V2 的 Draft Migration。

当前 v1.2 Draft Migration：

```text
V3__data_sync_auto_create_table.sql
V4__data_sync_column_mapping.sql
```

V3 增加 Task `auto_create_table`，默认关闭；V4 增加可空 `mapping_config`，NULL 保持旧任务隐式同名映射。两者尚未成为正式 Release Migration；Release Freeze 时按规则与其它 v1.2 Draft 统一收口。

Release Freeze 时：

- 如果 v1.2.0 没有 Schema 变化，不创建空 Migration。
- 如果 v1.2.0 有 Schema 变化，并且 Draft 尚未进入不可重建共享历史，则将同版本 Draft 收口为最多一个正式 Release Migration。
- 在当前发布链下，v1.2.0 的下一个正式 DB Migration 预期为 `V3__v1_2_0.sql`；如果发布链在冻结前发生变化，应以当时已发布的最大 Flyway Version 为准。

## 5. Development Rules

v1.2.0 开发阶段：

- 新能力必须更新对应 capability contract，而不是只改实现。
- Release Scope 未冻结前，不提前创建正式 Tag / Release。
- `1.2.0-SNAPSHOT` 只表示开发线，不表示 Release Candidate。
- 日常 PR 可以使用条件 CI；正式 Release 仍必须执行 Full Backend Acceptance。
- Release Freeze 前允许对当前版本未发布的 Draft Migration 做安全 squash。
- 已发布 v1.0.0 / v1.1.0 Release Evidence 与 Migration 不得因 v1.2 开发回改。

## 6. Current Explicit Non-Goals

当前已进入 Development，但以下能力尚未进入已承诺实现范围：

- Logical Table Persistence。
- Catalog Refresh / Schema Diff。
- DDL Sync / Automatic Schema Evolution。
- Multi-table Task。
- Transform。
- PostgreSQL CDC。
- Distributed Runtime / Worker / HA / fencing。
- Exactly-once transaction coordination。

已发布的 `V1__baseline.sql` / `V2__v1_1_0.sql` 继续永久冻结；v1.2 开发不回改 v1.1.0 Final Evidence。
