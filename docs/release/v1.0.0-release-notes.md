# Yak Ops v1.0.0 Release Notes

状态：Released

目标版本：`1.0.0`

目标 Tag：`v1.0.0`

Yak Ops v1.0.0 是第一个稳定发布版本，目标是提供一条可部署、可验收、可追溯的数据集成核心路径。

## 1. V1 核心能力

### 平台

- 用户登录 / 退出 / 当前身份。
- 用户管理。
- Workspace 生命周期、成员关系与请求隔离。
- 用户级 Workspace 选择保持。
- 用户偏好、收藏与常用数据源类型。

### 数据源

内置支持：

```text
MySQL 5 / 8
PostgreSQL
Oracle
```

支持 Datasource CRUD、真实连接测试、批量删除 / 连通性测试、Catalog Metadata、Structured JDBC Connection、Advanced Properties，以及 MySQL 5 / 8 Driver 隔离。

### 离线同步

Source：

```text
MySQL
```

Target：

```text
MySQL
PostgreSQL
Oracle
```

写入方式：

```text
APPEND
OVERWRITE
UPSERT
```

其中 UPSERT 使用目标数据库原生语义：

```text
MySQL       → ON DUPLICATE KEY UPDATE
PostgreSQL  → ON CONFLICT DO UPDATE
Oracle      → MERGE INTO
```

支持字段自动映射、JDBC Source split、Source parallelism、手工运行、Stop、Instance 历史与 `readRows / writeRows` 指标。

### 实时同步

Source：

```text
MySQL CDC
```

Target：

```text
MySQL
PostgreSQL
Oracle
```

支持：

- Debezium initial snapshot。
- MySQL Binlog continuous streaming。
- INSERT / UPDATE / DELETE。
- JDBC CHANGELOG apply。
- Checkpoint。
- persisted offset / schema history。
- 同一 Task + 同一 `definitionVersion` 停止后从已完成 offset 继续。
- Instance 运行状态与事件指标。

V1 的实时恢复语义是：

```text
at-least-once
```

不声明 exactly-once。

### 任务生命周期

Data Integration 负责：

- Task Definition。
- Save / Save & Publish。
- Publish / Unpublish。
- `definitionVersion`。

Operations Center 负责：

- 离线任务运行 / Stop。
- 实时任务 Start / Stop。
- Instance 列表 / 详情。
- 运行态观察。

## 5. 部署要求

- Java 21。
- Yak Ops 元数据库必须可用。
- 生产环境必须显式配置 `YAK_OPS_DATASOURCE_MASTER_KEY`。
- 示例默认密码只用于本地 / 演示环境，生产环境必须替换。
- Realtime CDC 状态目录必须持久化，容器替换 / 回滚不能清理 `${yak.ops.home}/data`。
- MySQL CDC Source 必须满足 ROW Binlog 与连接器所需权限。

Compose 支持：

- `compose.yaml`：包含 MySQL。
- `compose.without-mysql.yaml`：使用外部 MySQL。

## 6. Known Limitations

以下限制属于 V1 明确边界，不是 Release Blocker：

- Realtime 为 at-least-once，Checkpoint 后少量未确认事件在恢复时可能再次消费。
- 不支持 exactly-once transaction coordination。
- Offline Source 当前只承诺 MySQL。
- Realtime Source 当前只承诺 MySQL CDC。
- 目标表需要预先存在，不支持 Auto Create Table。
- 不支持 DDL propagation / Schema Evolution。
- 不支持 Transform。
- 不支持 Multi-table Task。
- 不支持 Scheduler / Cron。
- 不支持自动重试策略。
- 不支持 Distributed Runtime / Worker / HA。
- 应用重启后旧的 active Instance 会标记为 `LOST`；Realtime 通过新 Instance + persisted connector state 继续，不复活旧 Instance。
- Offline `OVERWRITE` 会先清空目标表，再执行写入；后续写入失败不会自动恢复清空前的数据。
- 启用 Offline split 后，不承诺多个 split 共享一个整表一致性快照时点。

## 7. V1 Non-Goals

以下能力明确进入后续版本规划，不阻塞 v1.0.0：

- 自动建表与逻辑建模。
- 调度系统。
- 自动重试。
- 分布式执行。
- Exactly-once。
- DDL / Schema Evolution。
- Transform。
- Multi-table Sync。
- 通用 Enterprise RBAC。

## 8. Database Migration

`v1.0.0` 是 Flyway baseline 的冻结点。

正式 Tag 创建后：

```text
V1__baseline.sql = immutable
```

后续数据库变化必须通过新的 Migration，例如：

```text
V2__*.sql
V3__*.sql
```

不得回改已发布的 V1 baseline。
